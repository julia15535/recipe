# Codex — независимый советник (правило владельца, как в sup2/remlab/julia)

Codex CLI (`codex exec`, read-only sandbox) — советник: он лучше исследует. Порядок всегда:
**свой краткий вывод → вопрос Codex → сверка по коду/тестам/источникам → решение и
ответственность мои.** Советник — не начальник: его ответы проверять и оспаривать, давать ему
максимум контекста (цифры, код, требования), а не скупой промпт.

Синтаксис: `codex exec --ephemeral --sandbox read-only -C /home/pakar/igor/recipe "<промпт>"`
(`-C` — только корень git-репо). Постоянная сессия (если заведём) — id в
`core/access-and-integrations.md`; тогда `codex exec --sandbox read-only -C /home/pakar/igor/recipe
-o answer.md resume <ID> - < prompt.md` (флаги ДО `resume`). Два `resume` одной сессии параллельно
не запускать — конфликтуют. Выводы Codex в память — с провенансом `external:codex`.

**ОБЯЗАТЕЛЬНО советоваться до действий:**
1. Причина дефекта не очевидна или первый фикс не сработал (root cause, регрессы).
2. Архитектурные решения: стек, схема БД и миграции, иерархии (категории, ингредиенты), устройство
   поискового индекса, контракты между модулями, очереди ИИ-импорта.
3. Нормы предметной области — с источниками и перепроверкой в интернете: правила округления
   ингредиентов, граммовые эквиваленты единиц, усреднённое КБЖУ, кулинарная разумность пересчёта.
4. Данные: справочники ингредиентов и КБЖУ, дерево каталога, промпты и схема ИИ-структурирования.
5. Любой новый план/метаплан и крупные правки плана — на критику ДО показа владельцу.
6. Разбор внешних оценок (замечания владельца, аудиты).
7. Рискованные изменения: безопасность и вход владельца, миграции, трудно откатываемое, прод.

**НЕ надо:** тривиальные правки текста/форматирования, очевидные однострочные фиксы, рутинные
команды (тесты/сборка/деплой), вопросы, уже закрытые в памяти/ADR без нового аргумента.
