## Цель
Владелец в кабинете вставляет текст рецепта в том виде, как пишет сейчас (как вафли), видит, как он будет
выглядеть на сайте, и сохраняет черновиком или публикует. Рецепты хранятся в базе; исправление — вставить
новую версию текста. Публичные страницы сайта — следующий план (они возьмут рецепты из этой базы).

## Источник задачи
Владелец 02.10 после входа: «А как рецепты загружать? там нет кнопки. И ещё когда перехожу на сайт, тоже
ничего нет» → «давай проработаем загрузку». Ответы на вопросы (все — рекомендованные): **вставить текст**
(окно в кабинете; телефон и компьютер); **формат — как пишу сейчас** (сайт понимает её стиль, непонятное
подсвечивает до сохранения); **сначала кабинет**, публичный сайт — следующим шагом; **пока без фото**;
правка — **загрузить заново** (решение того же дня). Образец её текста — `_intake/_processed/recipes/vafli-iz-tvoroga.md`.

## Как это выглядит для владельца
1. Кабинет → «Мои рецепты»: список (название, «Черновик» / «Опубликован», дата изменения) и «Добавить рецепт».
2. «Добавить рецепт» → большое поле «Вставьте текст рецепта» → «Проверить».
3. Предпросмотр — как страница рецепта на сайте + блок «Что поправить»: номер строки, сама строка и простое
   объяснение. Ошибки не дают сохранить (нет названия, раздела, ингредиентов или шагов; не отмечен основной
   ингредиент — сайт подсказывает кандидата, но выбрать должна она; у основного нет точного количества; у
   ингредиента нет ни количества, ни «по вкусу / по желанию / щепотка»; строка не понята). Предупреждения
   (неизвестный тег, склеенное продолжение шага) сохранить дают. Узнанное («завтрак» → раздел «Завтраки»)
   видно в самом предпросмотре, а не в замечаниях.
4. Новый рецепт: «Исправить текст» (назад, текст сохранён) · «Сохранить черновик» · «Опубликовать».
5. У рецепта: «Посмотреть», «Изменить» (поле с текущим текстом → «Проверить» → «Сохранить»: рецепт
   заменяется целиком, адрес и статус не меняются), «Опубликовать» / «Снять с публикации», «Удалить» —
   только черновик, с подтверждением. Пока сайт не открыт — у опубликованного подпись «появится на сайте,
   когда откроем страницы рецептов».

## Разбор текста (без ИИ, ADR-0008) — `lib/domain/recipe-text/`
Чистые функции; разбор по блокам (заголовок → «Теги:» → «Ингредиенты:» → «Приготовление:»): правила
ингредиентов действуют только в блоке ингредиентов, тире в шагах («5–7 минут», «6-7 минут») — просто текст.
- **Название** — первая непустая строка; всегда убираются «Название:» / «Рецепт:»; «Рецепт» без двоеточия —
  только перед словом с заглавной («Рецепт Творожные вафли» → «Творожные вафли»; v1 «Рецепт вафель из
  творога» остаётся как есть — поправит в тексте).
- **«Теги:» / «Разделы:»** — каждый элемент по словарю форм: раздел (порядок сохраняется, первый — основной)
  или тег состава; неизвестное — предупреждение. Парсер отдаёт `code`, сервер находит id.
- **«Описание:», «Время:», «Выход:» / «Порции:»** — необязательны («4 шт», «4 вафли», «4 порции»).
- **Ингредиенты**: маркер строки — ●, •, *, «-»/«–» в начале, «1.»/«1)»; разделитель имени — «—», «–»,
  «:» или «-» **с пробелами вокруг** («лук-порей», «0,5%» остаются в имени); слеши — часть имени.
  Количество справа: целое, «0,5», «½», «1½», «⅓», диапазон «½–1»; без разделителя — только «число +
  известная единица» в конце («молоко 1ст л»). Единицы — к виду сайта («ст л», «ст.л.», «1ст л», «столовая
  ложка» → «ст. л.»; «чл» → «ч. л.»; «шт» → «шт.»). Без числа — только явные «щепотка», «по вкусу», «по
  желанию». Скобки — пометка. «основной ингредиент» / «(основной)» — основной; два основных, диапазон или
  нет числа у основного — ошибка. Непонятная строка не пропадает — ошибка с её текстом.
- **Шаги** — «1.» / «1)» или маркеры; текст шага сохраняется буквально; продолжение строки приклеивается к
  шагу с предупреждением.
- **«Советы:»** — пока не сохраняем: предупреждение «советы добавим позже» (реальных текстов с советами нет).
- **Количества — точные дроби** (числитель/знаменатель, сокращаются: «2/6» → «1/3»), не числа с плавающей
  точкой; пересчёт и показ «⅓», «1⅓» — от дробей.
- Замечание: `{ code, severity: error|warning, line, raw, message }` — тесты и экран опираются на `code`.
- Пределы: 20 КБ в UTF-8 (`Buffer.byteLength`), строк ≤ 300, длина строки ≤ 500, ингредиентов ≤ 60,
  шагов ≤ 40; без управляющих символов. То же — CHECK в БД, где применимо.

## База (миграция 0002, expand; по критике Codex)
- `sections` (id uuid, `code` UNIQUE, `parent_id`, `position`) + `section_localizations` (раздел, `locale`,
  `label`, `slug`; UNIQUE (`locale`, `slug`)) — 11 разделов с постоянными id/code, строки `ru` (EN-подписи
  ещё не утверждены — строки `en` добавит план сайта); `composition_tags` (id, `code`, `position`) + локализации — 5 тегов. Словари распознавания и
  цвета — в коде, данные каталога — в БД.
- `recipes`: id uuid, `status` (`draft|published`), `source_text` (CHECK ≤ 20480 байт), `revision`,
  `main_ingredient_id` NOT NULL и `primary_section_id` NOT NULL — составные отложенные FK на свои строки
  (ровно один основной ингредиент и основной раздел гарантирует БД), выход (`yield_num`, `yield_den`),
  `created_at`, `updated_at`, `published_at` (первая публикация, не очищается; видимость — `status`).
- `recipe_localizations` (рецепт, `locale`, `slug`, `title`, `description`, `time_text`, формы выхода;
  PK (рецепт, locale), UNIQUE (`locale`, `slug`)) — сейчас только `ru`. Slug: транслит (`ё`, регистр),
  только `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 80 символов, пустой → `recipe-<короткий id>`, коллизия — повтор
  вставки с `-2`, `-3`; при замене текста не пересчитывается.
- `recipe_sections` (рецепт, раздел, `position`), `recipe_composition_tags` (рецепт, тег, `position`).
- `recipe_ingredients`: id uuid, рецепт, `position`, `display_name`, `quantity_kind` (`exact|range|none`),
  `amount_num/den`, `amount_max_num/den`, `unit`, `note`; CHECK: знаменатели > 0, числа > 0, exact — без
  max, range — min ≤ max (перекрёстным умножением), none — без чисел и с пометкой; разумный максимум.
- `recipe_steps` (id, рецепт, `position`, `text`). У дочерних таблиц: `position ≥ 0`, UNIQUE (рецепт,
  position), FK ON DELETE CASCADE, индексы по обратным ключам.
- Права: default privileges дают `recipe_app` DML; тест — CRUD новых таблиц разрешён, DDL запрещён.

## Сохранение
- Server Actions: `previewRecipe(text)` — `requireOwner()`, пределы, чистый разбор; в БД не пишет.
  `saveRecipe(text, intent, recipeId?, expectedRevision?)` — снова `requireOwner()` и **повторный разбор
  именно текста**: готовые ингредиенты, статус, slug или id разделов от браузера не принимаются.
- Транзакция: проверка `revision` (другая вкладка уже сохранила → «Рецепт уже изменён в другой вкладке —
  обновите страницу»), `revision + 1`, обновить рецепт и локализацию, удалить и вставить строки, отложенные
  FK проверяются при commit; ошибка — старая версия целиком на месте.
- Слои: `lib/server/recipes/` — запросы к БД без проверки владельца (следующему, публичному плану нужно
  чтение опубликованного); проверка владельца — в страницах и действиях кабинета.
- Без `dangerouslySetInnerHTML`, Markdown и HTML из текста; классы не собираются из текста; XSS-строка
  в предпросмотре — просто текст. Кабинет уже динамический с CSP на nonce.

## Предпросмотр = будущая страница сайта
Модель показа рецепта (`RecipeView`: дроби, стабильные id строк, готовые ссылки и подписи) и компоненты в
`components/recipe/` (шапка, ингредиенты с пересчётом — маленький клиентский островок, шаги — серверные;
без фото — без цветной заглушки). Прототипы `/admin/ui` переходят на них через адаптер демо-данных
(e2e прототипов остаются зелёными); ключи строк — id, а не название.

## Скоуп — что входит
1. `lib/domain/recipe-text/` (разбор, словари, дроби, пределы) + тесты, в т.ч. золотые на блоках v1/v2.
2. Миграция 0002 + Drizzle-схема (отложенные FK — ручным SQL в миграции) + `lib/server/recipes/`.
3. `RecipeView`, `components/recipe/*`, адаптер прототипов; пересчёт от дробей.
4. Кабинет: «Мои рецепты» на `/admin`, `/admin/recipes/new`, `/admin/recipes/[id]`, `/admin/recipes/[id]/edit`;
   Server Actions с `requireOwner()`; mobile-first (≥ 44 px, состояния пусто/ошибка/успех), axe, 375/1280 px.
5. Тесты (ниже) + `pnpm test:db` + e2e.
6. Память: ADR (схема рецептов: дроби, локализации, справочники каталога; разбор «как пишет владелец»
   без ИИ), `core/recipe-import.md`, `core/data-models.md`, `domain/recipe-model.md`, `core/catalog.md`,
   `project-state.md`.

## Скоуп — что НЕ входит
Публичные страницы сайта и поиск по базе (следующий план, там же `updateTag` после commit), фото, PDF/Word,
ИИ-разбор, EN-содержимое, справочник ингредиентов и поиск по ингредиенту (позже — nullable `ingredient_id`,
expand), советы, округление, КБЖУ, правка по полям, история slug.

## Риски
- Разбор не узнает новый оборот → ошибка с номером строки и её текстом; словари пополняем по её рецептам.
- Обязательная пометка основного добавляет шаг владельцу — зато пересчёт не «якорится» на ложке масла.

## Критерии приёмки
- [ ] Вафли v2 как есть → «Творожные вафли», раздел «Завтраки», тег «Белок», творог 275 г — основной,
      ½ ч. л., «щепотка», перец/травы/паприка — «по желанию», масло ½ ст. л., молоко 1 ст. л. «если творог
      сухой», 5 шагов дословно; v1 → диапазон ½–1 ч. л. и название как в тексте
- [ ] «5–7 минут» / «6-7 минут» в шагах не становятся ингредиентами; ⅓, ⅔, 1⅓ хранятся и пересчитываются точно
