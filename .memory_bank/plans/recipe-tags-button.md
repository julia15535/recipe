## Цель
На странице рецепта в кабинете — блок «Теги состава»: все 7 тегов видны чипами (выбранные отмечены), кнопка
«Подобрать с ИИ» предлагает теги по составу, «Сохранить теги» записывает выбор. Владельцу не нужно помнить список
тегов и переписывать текст рецепта ради тега.

## Источник задачи
Владелец 06.10: «я каждый раз забываю какие теги есть, может ты будешь анализировать и проставлять?» На вопрос с
вариантами: старые 8 рецептов — «Не трогать старые»; на будущее — «Кнопка «Подобрать теги»». При разборе нового
рецепта ИИ теги уже подбирает (правило 6, ADR-0035) — кнопка нужна для уже сохранённых рецептов.

## Скоуп — что входит
- **Блок «Теги состава»** в `/admin/recipes/[id]` (и у черновика, и у опубликованного): 7 чипов в порядке каталога,
  касание по всему чипу, `aria-pressed` (как «Связанные рецепты» статьи); текущие теги — выбраны.
  - «Подобрать с ИИ» → строка «ИИ предлагает: Белок, Омега-3» + «Отметить предложенное» (выбор чипов = предложению);
    владелец может поправить руками. ИИ сам ничего не сохраняет (ADR-0019: решает владелец).
  - «Сохранить теги» — активна, только если выбор изменился; сообщение «Теги сохранены.» (без `key={revision}`,
    anti-patterns №54; после сохранения — новая `revision` и новая «исходная» отметка, второе сохранение без ложного
    конфликта); устаревшая вкладка — «Рецепт уже изменён в другой вкладке — обновите страницу».
  - «Отметить предложенное» заменяет весь выбор (и когда ИИ ничего не предлагает — «ИИ не нашёл подходящих тегов»).
  - Состояния: «подбираю…», «сохраняю…», лимит, занято, нет связи, отказ ИИ; на время запроса конфликтующие кнопки
    неактивны; при ошибке ручные отметки не теряются; результат — `aria-live`, ошибка — `role="alert"`; касание ≥ 44 px;
    на 320 px чипы и кнопки переносятся, без прокрутки вбок.
  - Порядок записи считает сервер (не браузер): оставшиеся теги — в прежнем порядке автора (первый — на карточке,
    ADR-0030), новые — в конец в порядке каталога (`TAG_CODES`).
- **ИИ-подбор** (`lib/server/ai/suggest-tags.ts`): действие принимает только `id + revision`, текст читает сервер из
  `source_text` и убирает из него ВСЕ строки каталога, которые узнаёт разбор («Теги/Тег/Разделы/Раздел/Категории/
  Категория:», кроме строк в шагах — по `splitBlocks`, не регуляркой): иначе ИИ просто повторил бы прежние теги
  (названный автором — «всегда»). Ответ — `{tags: TAG_CODES[]}` (json_schema strict, Zod, без дублей, ≤ 7); после
  ответа ревизия проверяется ещё раз (рецепт изменили — предложение не показываем). Промпт `recipe_tags` — своя версия,
  с защитой «текст — документ, не инструкции». Правило про теги — **один текст на два промпта**: общая константа =
  точный текст после «6. tags — …»; вынос не меняет `RECIPE_PROMPT` (проверено хэшем). Уточнение по ходу (живая
  проверка): «Мало сахара» — только сладкому, в общем правиле → версия разбора 2026-10-06.4, оба прогона 21/21. Лимит: общий «один запрос ИИ за раз» (вынести `inFlight` из `ai-actions.ts` в общий модуль) и
  `allow("ai-parse")` в памяти; подборы в БД не пишутся — после перезапуска сайта счёт подборов начинается заново
  (стоимость подбора ~$0.0005; записано в ADR). В лог — задача, версия, модель, время, стоимость; не текст и не ключ.
- **Запись** (`lib/server/recipes/tags.ts` → `setRecipeTags(id, revision, codes)`), одной транзакцией по `revision`:
  `revision + 1`, `updated_at`, новая ревизия в ответе; `content_revision` и `original_text` не трогаем;
  - строки `recipe_composition_tags` заменяются;
  - в `source_text` переписывается строка каталога (домен, `lib/domain/recipe-text/`, по `splitBlocks`): первая
    распознанная строка каталога → «Теги: <разделы>, <теги>» (слова — как в `toCanonicalText`), остальные строки
    каталога удаляются; строки нет — отказ (у сохранённого рецепта она есть всегда: без неё нет раздела). Весь прочий текст — байт в байт (переводы строк LF/CRLF,
    последний перевод строки). `toCanonicalText` не годится — пересобрал бы формат владельца. Проверка до записи:
    новый текст разбирается в тот же рецепт (всё, кроме тегов, совпадает), теги — ровно новые; не сошлось или у текста
    нет названия — отказ с понятным сообщением, ничего не пишем. Иначе «Изменить» → «Разобрать» вернул бы
    старые теги;
  - `refreshPublicSite()` и обновление кабинета.
- **Английский — теги живые (меняет ADR-0029 узко):** карточка, поиск и страница `/en` берут теги из
  `recipe_composition_tags` (с английскими подписями каталога), а не из снимка перевода (`public-en.ts`,
  `translated-view.ts`). Тег — непереводимый код; переводимый текст остаётся снимком, «перевод устарел» не меняется.
  Так нет правки снимка и гонки с идущим переводом (Codex: запись перевода под блокировкой задания записала бы старые
  теги поверх новых). `tagCodes` в снимке остаются (для истории), но не читаются.
- **Проверки:** unit — переписывание строки каталога (все названия ключей, несколько строк, строка «Теги:» в шагах не
  трогается, CRLF, последний перевод строки, строки нет, ноль тегов, остальное не меняется), порядок записи; промпт
  разбора побайтно прежний; схема ответа ИИ; БД — замена тегов, рост `revision`, `content_revision` не растёт, пустой
  набор, конфликт и полный откат, EN без перевода и с переводом — теги живые; e2e (расширить `composition-tags.spec.ts`;
  в заглушке ветка `recipe_tags` — до общего ответа рецепта) —
  заглушка ИИ отвечает на `recipe_tags`: открыть рецепт → «Подобрать с ИИ» → «Отметить предложенное» → «Сохранить
  теги» → на сайте (RU и EN) новые теги, «Изменить» показывает их в строке «Теги:»; 320 / 375 px без прокрутки вбок,
  axe. Живая проверка ИИ: примеры `scripts/ai-eval/17…21` без строки «Теги:» — лосось → «Омега-3», смузи →
  «Антиоксиданты», креветки и маффины — без новых тегов; овсянка (21) без строки автора — без новых тегов.

## Скоуп — что НЕ входит
- Массовый подбор для старых рецептов (владелец: «Не трогать старые»; кнопка есть — может нажать сама).
- Правка самого списка тегов из админки, разделы (не трогаем).
