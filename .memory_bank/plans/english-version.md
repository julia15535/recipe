## Цель
У сайта появляется английская версия `/en`: те же разделы, рецепты, фото, поиск и пересчёт — на британском
английском. Рецепт переводит ИИ сам при публикации; владелец ничего не переводит вручную.

## Источник задачи
Владелец 02.10: «Английский тоже хочу, я же в Англии рекламирую его в инсте»; порядок «русский → фото → английский»;
03.10 после фото: «вроде все супер, что делаем дальше?» → «Английская версия». Решения владельца 03.10:
- перевод появляется на сайте **сразу** после публикации, без её проверки («Нет, пусть появляется сразу»);
- правка русского рецепта английский **не трогает**, пока она не нажмёт «Перевести заново» (до этого — «устарел», на
  сайте старый перевод) — «Не трогать, пока не нажму»;
- единицы — «как у меня»: г, мл, tbsp/tsp, cup (с подсказкой в мл); унций нет;
- `mycoruja.food` без языка — **по языку телефона**, кнопка EN/RU в шапке, выбор запоминается.
ADR-0009 (EN — ИИ-перевод, RU основной) — уточняется: ручной правки EN в этом плане нет (владелец не просила).

## Как будет
**Посетитель.** `/en` — главная «New recipes», каталог (Breakfast, Soups, …), страница раздела, рецепт (пересчёт,
округление, фото, «~ 4 servings»), поиск «By recipe / By ingredient». На `/en` — только рецепты с переводом. Кнопка
«RU/EN» в шапке ведёт на ту же страницу на другом языке (рецепт — на его английский адрес; нет перевода — на главную).
**Владелец (кабинет по-русски).** Опубликовала → через ~10 с английская версия на сайте. У рецепта строка «Английская
версия: готова / переводится… / устарела — вы меняли рецепт / не получилась» + «Перевести заново» + «Открыть
по-английски». Для уже опубликованных рецептов — «Перевести» (разово).

## Два этапа выкладки (критика Codex 03.10)
- **Этап 1 — без видимых изменений:** таблицы (расширение схемы), EN-названия каталога, пересчёт/округление/числа
  «по языку» в `lib/domain`, все русские надписи — в `messages`, провайдеры сообщений на сайте и в кабинете. Сайт
  остаётся только русским (`LIVE_LOCALES=["ru"]`); прогон всех e2e — русский сайт и кабинет не изменились.
- **Этап 2 — английский:** очередь переводов, ИИ-перевод, публичные чтения `en`, `/en`, кнопка RU/EN, hreflang,
  язык по телефону.

## Решения (критика Codex 03.10 учтена; факты проверены по коду)
1. **Хранение — агрегат из двух таблиц.** `recipe_localizations(en)` — единственный источник slug, названия,
   описания, времени и форм выхода (как у ru). `recipe_translations` — последний **готовый** снимок: выход (дробь),
   коды разделов, основного раздела и тегов, основной ингредиент, ингредиенты (английские имя и пометка,
   количество, каноничная единица, `roundingKind`), шаги, советы, `source_content_revision`, `schema_version`,
   модель и версия промпта. Пишутся вместе одной транзакцией; на `/en` рецепт виден только при наличии обеих
   (join). Снимок проверяется Zod при записи и при чтении (повреждённый → лог и «нет перевода»); в БД —
   `jsonb_typeof = object` и предел размера. Формы выхода: CHECK расширяется — ru 3 формы, en 2.
2. **Ревизия содержания.** Сейчас `recipes.revision` растёт и при публикации/снятии (`status.ts`), поэтому
   «устарел» по ней ложный → новая колонка `recipes.content_revision`, растёт только при замене текста рецепта;
   устарел = `snapshot.source_content_revision ≠ content_revision`. `setRecipeStatus` с тем же статусом — без
   изменений (идемпотентно).
3. **Очередь переводов** `recipe_translation_jobs` (recipe_id, locale, входной снимок русского рецепта на момент
   постановки, статус `queued | running | done | failed`, `lease_until`, token, попытки, ошибка). Публикация (и
   «Перевести»/«Перевести заново») в своей транзакции ставит задание (если готового перевода нет или владелец просит
   заново; активное задание не дублируется) → после commit `after(() => runJob(id))` (публикация не ждёт ИИ).
   `runJob`: захват аренды (CAS по token) → вызов ИИ вне транзакции (у роли `statement_timeout` 15 с) → короткая
   транзакция записи результата только если задание всё ещё его (token) → сброс кэша `recipes`, `catalog`,
   `search-index` через `revalidateTag(tag, { expire: 0 })` (в `after()` это работает — `after-context.js`
   выполняет revalidate; `updateTag` вне действия нельзя). Неудача — `failed`, **старый готовый перевод остаётся на
   сайте**. Поздний ответ старого задания ничего не перетирает.
4. **Подбор потерянных заданий.** `after()` — не очередь: деплой останавливает контейнер за 20 с, а ИИ ждём до 45 с.
   Раз в минуту процесс сайта (`instrumentation-node.ts`) подбирает задания `queued` и `running` с истёкшей арендой —
   через свой же внутренний адрес `/api/jobs/translations` с одноразовым секретом процесса (чтобы `revalidateTag`
   работал в контексте запроса Next). Серверу и деплою ничего не добавляется. Кабинет ещё и опрашивает статус, пока
   идёт перевод. **(на дополнительную проверку Codex)**
5. **Перевод — ИИ на входе (ADR-0008), тот же шлюз** (`openai/gpt-6-luna`, json_schema strict, 45 с). Модель
   возвращает **только тексты**: название, описание, время, 2 формы выхода, ингредиенты `{id, имя, пометка,
   своя единица?}`, шаги и советы `{id, текст}`. Количества, единицы, разделы, теги, основной — копирует код из
   входного снимка. Проверки: те же id в том же порядке, без дублей и пропусков, длины, без управляющих символов;
   числа, °C и проценты в тексте шагов/советов — заменяются метками до вызова и сверяются после (ИИ не может
   поменять температуру или граммы). Промпт: вход — недоверенный текст; точный перевод без «улучшений»; британский
   английский и кухонная лексика (courgette, coriander, aubergine, caster sugar, minced beef); меры не
   конвертировать, °C сохранить; бренды как есть; без Markdown. Slug — кодом из английского названия, коллизии
   `-2`; **при повторном переводе slug не меняется**. Версия промпта и модель — в снимке.
6. **Единицы и пересчёт по языку:** в снимке — каноничная единица и `roundingKind` (из русской строки, до
   перевода); `rounding.ts` возвращает коды (`pinch`, `upTo`, `weighEggs`), а не русские слова — текст подставляет
   компонент; единицы для показа: г/кг/мл/л → g/kg/ml/l, ч. л./ст. л./стак. → tsp/tbsp/cup («≈ 250 ml»), шт. — без
   единицы; авторские («пучок», «зубчик») — английская подпись от ИИ (`своя единица`). Числа и ввод: ru `1,5`, en
   `1.5`; формы выхода — `Intl.PluralRules` (ru one/few/many, en one/other). Стакан в расчётах — 250 мл, ст. л. 15,
   ч. л. 5 (сейчас малые стаканы считаются через 16 ст. л. ≈ 240 мл — выровнять).
7. **EN-каталог** (миграция по постоянным кодам; **названия и адреса — показать владельцу**): Breakfast
   `breakfast`, Soups `soups`, Salads `salads`, Mains `mains`, Sides `sides`, Starters `starters`, Baking `baking`,
   Desserts `desserts`, Sauces `sauces`, Drinks `drinks`, Preserves `preserves`; теги Protein, Fibre, Healthy fats,
   Low sugar, Iron. Число рецептов раздела на `/en` — только с готовым переводом.
8. **Надписи** — namespaces в `messages/{ru,en}.json` (Recipe, Search, Catalog, Site, A11y); клиенту — только нужные
   namespaces (сейчас провайдер сайта отдаёт все сообщения); кабинет и прототипы получают свой провайдер с русским
   подмножеством (общие компоненты рецепта используются и в кабинете — без провайдера он сломается). Поиск: «или» →
   `or`, сортировка по языку.
9. **Маршрутизация:** `localeDetection` включён, cookie выбора — на год; `/` — только перенаправление (`no-store`,
   `Vary: Accept-Language, Cookie`); страницы с `/ru` `/en` cookie не читают. Кнопка языка — по сущности: главная →
   главная, раздел (код) → его slug, рецепт (id) → slug перевода или `/en`, поиск → без `q` и `i`. hreflang — явная
   пара адресов: у рецепта без перевода — только ru; x-default — только у главной. OG `ru_RU` / `en_GB`. Поисковикам
   по-прежнему закрыто.

## Скоуп — что входит
Этап 1: миграция (content_revision, EN-каталог, таблицы переводов и заданий, CHECK форм выхода), domain по языку
(единицы, числа, формы, коды округления), вынос надписей, провайдеры, `setRecipeStatus` идемпотентен; регрессия ru.
Этап 2: `lib/server/ai/translate-recipe.ts` (промпт, схема, проверки), `lib/server/recipes/translations.ts` (очередь,
аренда, запись), подбор заданий, действия и статус в кабинете («Английская версия: …», «Перевести», «Перевести
заново», «Открыть по-английски», опрос статуса), публичные чтения `en` (карточки, раздел, рецепт, поиск, счётчики),
`/en`, кнопка языка, alternates, detection. Тесты: unit (единицы, числа, формы, проверка ответа ИИ, метки чисел),
БД (снимок, устаревание, гонки: две генерации, правка во время перевода, снятие во время перевода, неудача повтора
сохраняет старый перевод, поздний ответ не перетирает), e2e (заглушка ИИ по `schemaName`: опубликовать → `/en` в
пределах минуты, правка → «устарела», «Перевести заново», кнопка RU/EN, `/` по языку браузера).

## Скоуп — что НЕ входит
Ручная правка английского текста в кабинете, кабинет на английском, перевод прототипов, иные языки, открытие
поисковикам, справочник ингредиентов, «Подборка недели».

## Риски
- Качество перевода без проверки владельца — промпт, метки чисел, проверка структуры; «Перевести заново».
- Перезапуск сайта во время перевода — аренда истекает, задание подбирается за минуту.
- Объём правок компонентов (этап 1) — регрессия русского сайта и кабинета ловят существующие e2e.

## Критерии приёмки
- [ ] Опубликовать рецепт → ≤ 1 мин на `/en` (главная, раздел, рецепт, поиск) по-английски, фото и пересчёт работают

- [ ] `/` с английским браузером → `/en`, с русским → `/ru`; кнопка RU/EN ведёт на ту же страницу; hreflang ru/en
