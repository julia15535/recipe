## Цель
На сайте появляется раздел «Статьи»: страница со свободным текстом (заголовки, абзацы, списки) и несколькими фото
между абзацами, со связанными рецептами; на странице рецепта — блок «Связанные статьи». Первая статья — «Вафли:
варианты подачи» (с творожным сыром и рыбой, с ветчиной) со ссылкой на «Творожные вафли». Английская версия статей —
следующим отдельным планом (`articles-en`).

## Источник задачи
Владелец 04.10: «если я хочу вариативность делать… вафли, творожный сыр, рыба, или с ветчиной. как лучше сделать?» →
«не может отдельной страничкой, где будет просто текст и может фоточки» → «Да, составь план». Решения владельца 03.10
(`project-state.md`, «Отложено»): отдельный раздел (список + страница), свободный текст с заголовками и списками, НЕ
подборки карточек; текст пишет владелец, ИИ только размечает и не пишет за неё; EN — автопереводом после публикации;
несколько картинок внутри текста, не одна обложка; главный риск — места картинок при «Изменить».

## Как будет (для владельца)
- Кабинет → «Мои статьи» → «Новая статья»: поле «Название» (пишет она) и поле текста — вставить как есть →
  «Разобрать» → предпросмотр как на сайте. ИИ только помечает, где заголовок, абзац, список — слова берутся из её
  текста кодом, изменить их ИИ не может. Нет связи с ИИ — «Разобрать без ИИ» (абзацы по пустым строкам, списки по
  «-»/«•»/«1.», заголовки по «#»).
- Фото: после первого «Сохранить черновик» — в предпросмотре между абзацами «Добавить фото сюда» (как у рецепта:
  уменьшение в браузере, кадр 4:3 — ADR-0028); подпись — по желанию; до 10 фото. В тексте на месте фото появляется
  строка-метка вида «[Фото Q7K2]» — её можно перенести в другое место текста, удалить (с вопросом «убрать фото?»).
- «Связанные рецепты»: выбрать из своих (поиск по названию); снятый с публикации рецепт на сайте не показывается, связь
  сохраняется.
- «Сохранить черновик» / «Опубликовать» / «Снять» / «Удалить черновик» — как у рецептов.
- На сайте: «Статьи» — список (фото, название, первые строки) и страница статьи; на рецепте — «Связанные статьи».

## Как будет (устройство; критика Codex 04.10)
- **Хранение (миграция 0010):** `articles` (статус, `published_at`, `revision` — защита от второй вкладки,
  `content_revision` — только при смене текста/блоков/подписей, для будущего перевода; `source_text` — текст с метками
  фото, источник для «Изменить»; `body jsonb` — проверенные блоки по Zod-схеме с версией: heading(h2/h3) / paragraph /
  list(маркер или нумерация) / photo, у блока стабильный id; пределы в БД); `article_localizations` (ru: slug,
  название, анонс = первый абзац с обрезкой — ИИ анонс не пишет); `article_photos` + `article_photo_files` (свои
  таблицы по образцу рецепта, не общий «медиа»-слой; у фото постоянный id и номер версии кадра — адрес
  `/media/article/{photoId}/{version}/{file}`; подпись, alt); `article_recipes` (PK статья+рецепт, порядок, каскады);
  `article_imports` (разбор с сервера по id, как `recipe_imports` — готовым блокам из браузера не верим).
- **Разметка ИИ:** текст режется на строки; метки фото — только целой строкой (метка внутри абзаца, повтор,
  неизвестный код, > 10 фото — ошибка до ИИ). ИИ получает пронумерованные строки (без меток) одним запросом и
  возвращает только разметку: какие строки — заголовок, какие — абзац (группа строк), какие — пункты списка. Код
  проверяет: каждая строка использована ровно один раз и по порядку; текст блоков код копирует из её строк (одиночный
  перенос внутри абзаца — пробел, пустая строка — граница). Фото-блоки код ставит по меткам. Свой промпт и json_schema,
  тот же шлюз (ADR-0024), лимит разборов общий с рецептами.
- **«Добавить фото сюда»** — у каждого блока известен диапазон строк источника → метка вставляется в `source_text` после
  него, сохранение — по `revision`. Загрузка, у которой ещё нет места, — в «Фото без места», не теряется.
- **Безопасность и рендер:** только текст как React-узлы, без HTML/markdown; ссылок внутри текста в этапе 1 нет
  (связанные рецепты закрывают нужду). Пределы: текст ≤ 20 КБ, ≤ 300 строк, ≤ 100 блоков, ≤ 10 фото, заголовок ≤ 160,
  абзац/пункт ≤ 2000, `body` ≤ 256 КБ. Обработка фото — общий с рецептами лимит (30 в час, одна за раз; ключ лимита —
  общий). alt фото = подпись, иначе ближайший заголовок перед фото, иначе название статьи (владельцу не нужно писать
  отдельно).
- **Сайт:** `/{locale}/articles`, `/{locale}/articles/[slug]` (`/en/articles` до плана EN — пусто/404); кэш как у
  рецептов (`<Suspense>` → `io()` → `"use cache"`), теги `articles`, `article:{id}` и перекрёстный сброс со связанными
  рецептами; везде только опубликованное с обеих сторон; превью ссылки — первое фото (`og.jpg`).
- **Навигация (решение владельца 06.10):** компьютер — ссылка «Статьи» в строке шапки перед «Поиск»; телефон — строка
  «Статьи» в листе каталога (не 12-й раздел каталога); блок «Статьи» на главной под «Новыми рецептами».
- **Бэкап:** до 5 файлов по ≤ 1 МБ на фото → 10 фото ≈ до 50 МБ на статью; замер реальных размеров, проверка
  восстановления копии с 10 фото, размер таблиц — в `core/deployment.md`.

## Скоуп — что входит (этап 1, RU), по шагам-коммитам
1. ADR + миграция 0010 + Zod-модель документа + DB-тесты (статусы, каскады, связи, пределы).
2. `lib/domain/article-text/`: строки и метки, разбор без ИИ, сборка блоков по разметке, проверка «каждая строка
   ровно раз», `source_text` ↔ блоки туда-обратно (unit).
3. ИИ-разметка: схема, промпт, `article_imports`; живая проверка на 6 текстах (подпись Instagram без абзацев, заметка
   со списками, текст с заголовками, со смайликами, длинный, с метками фото).
4. Кабинет: список, редактор, статусы (без фото и связей).
5. Фото статьи: таблицы, обработка (общий `lib/server/media/process.ts`), маршрут отдачи, «Добавить фото сюда»,
   перенос/удаление метки, «Фото без места».
6. Связанные рецепты, сайт RU (список, страница, блок на рецепте), кэш и превью, навигация.
7. e2e (статья с 2 фото и рецептом: создать → опубликовать → на сайте → «Изменить» переставить метку → фото на новом
   месте; удалить метку; 320 / 375 / 1280 px, axe), verify, память (`core/articles.md` + `domain/articles.md`, ADR,
   `core/data-models.md`, `domain/screens.md`, `core/architecture.md`, `core/deployment.md`).

## Скоуп — что НЕ входит
Английская версия статей (отдельный план `articles-en`: своя очередь `article_translation_jobs`, общий исполнитель и
подборщик; на `/en` связанные рецепты — только с переводом). Рубрики/теги статей, комментарии, ссылки внутри текста,
стихотворные переносы строк, видео, ИИ-тексты, статьи в общем поиске, поисковики (сайт закрыт).
