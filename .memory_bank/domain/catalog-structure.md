# Структура каталога — стартовое дерево (ТЗ §4–5)

> Сид для БД на старте. Структура **редактируется из админки** (добавить / удалить / объединить),
> поэтому это не жёсткий справочник, а начальное наполнение. Ориентир классификации — gotovim-doma.ru
> (интерфейс и сложность НЕ копируем). В скобках — id категории на gotovim-doma
> (`https://gotovim-doma.ru/category/<id>-…`). «+» — добавить сверх gotovim-doma по ТЗ.

## Верхний уровень — 11 разделов (ADR-0018, владелец 01.10; все 11 мест видны всегда, пустые бледные — ADR-0020)
Завтраки · Супы · Салаты · Горячее · Гарниры · Закуски · Выпечка · Десерты · Соусы (в ТЗ §4 — «Соусы
и заправки») · Напитки · Заготовки. Было (ТЗ, ADR-0001): Закуски · Салаты · Супы · Вторые блюда ·
Выпечка · Десерты · Напитки · Соусы · Заготовки · Разное.
- «Вторые блюда» → **«Горячее»** (подкатегории ниже — его).
- **«Завтраки»** — новый (приём пищи, не тип блюда): каши, яйца, сырники/творожные, блины/оладьи,
  бутерброды — черновик, пересечения с другими разделами допустимы (рецепт в нескольких разделах).
- **«Гарниры»** — поднят из подкатегории «Вторых блюд»: картофель, крупы, овощи, бобовые, грибы — черновик.
- **«Разное» убрано:** творог/молочное и яйца → Завтраки/Горячее, специи и приправы → Соусы, украшения
  блюд → Десерты (черновик, решить при сиде БД).
- Сид подкатегорий — до импорта реальных рецептов, в плане схемы БД.

## Требования к модели дерева
- Глубина — минимум 3 уровня (Салаты → Классические → Оливье); лучше произвольная.
- Рецепт: одна категория + подкатегория + при необходимости более глубокий уровень (ТЗ §6).
- Операции админки: добавить, переименовать, удалить, **объединить** (перенос рецептов и редирект
  старого URL — иначе SEO теряет страницы).

## Особенности состава (ADR-0019, ADR-0035) — отдельная группа тегов
Белок · Клетчатка · Полезные жиры · Омега-3 · Мало сахара · Железо · Антиоксиданты (EN: Protein · Fiber · Healthy
fats · Omega-3 · Low sugar · Iron · Antioxidants) — порядок фильтра поиска (`composition_tags.position`, коды —
`TAG_CODES` в `lib/domain/catalog.ts`; новые два — миграция `drizzle/0011_composition_tags_omega_antioxidants.sql`).
Ставит владелец по своему суждению; ИИ при импорте только предлагает (названный автором тег — всегда; сам — коротко
по правилу 6 `lib/server/ai/recipe-prompt.ts`, у новых двух — списки ниже почти дословно). Памятка:
- тег — если продукт **заметная часть блюда**, не украшение, не щепотка, не масло для жарки или смазывания;
- Белок — мясо, птица, рыба, яйца, творог, сыр, бобовые; Клетчатка — заметная доля овощей, фруктов,
  бобовых, цельных круп, орехов, семян; Полезные жиры — орехи, семена, авокадо, оливковое и др.
  нерафинированные масла, жирная рыба; Железо — красное мясо, печень, гречка, бобовые, шпинат;
- Омега-3 — жирная рыба (лосось, скумбрия, сельдь, сардина, форель), икра заметной порцией, лён / чиа / конопляное
  семя / грецкий орех заметно, льняное или рапсовое масло в заправке; НЕ креветки, кальмары, мидии, гребешки, белая
  рыба (у них EPA/DHA мало — NIH ODS, `external:codex`);
- Антиоксиданты — только явные случаи: тёмные ягоды как основа (черника, ежевика, чёрная смородина, клюква), гранат,
  какао / тёмный шоколад как основной вкус, чай / матча как основа напитка; обычные овощи и фрукты — нет (иначе тег
  был бы почти везде; общие заявления о пользе не подтверждены — EFSA, NCCIH, `external:codex`);
- «Мало сахара» — по оценке владельца («я решаю»), числового порога нет.
Строка «Теги:» узнаёт «омега-3» / «омега 3» / «омега3» (не «омега»), «антиоксиданты» / «антиоксидант» (`lib/domain/catalog.test.ts`).
На странице рецепта — рядом со временем, у каждого тега свой цвет по ассоциации, без подписи (ADR-0021):
`protein` персик, `fiber` олива, `healthy-fats` золото, `omega-3` морская волна, `low-sugar` пыльно-голубой, `iron`
ягодный, `antioxidants` черничный — токены `--color-tag-*` в `styles/brand.css`, ключ — стабильный код тега. Тег
значит только «в рецепте заметно таких продуктов»; появятся реклама/партнёрские продукты — формулировки пересмотреть
(заявления о пользе).
