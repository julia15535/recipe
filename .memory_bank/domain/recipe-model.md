# Модель данных рецепта (ТЗ §6, §8, §10–11, §22 + продуктовые решения)

> Статус: **схема рецептов реализована** (ADR-0023, план recipe-upload; таблицы и правила —
> `domain/recipe-upload.md`). Ниже — логическая модель ТЗ целиком; «предложение» — то, что ещё не сделано
> (справочник ингредиентов, КБЖУ, исходники импорта, EN). Фото — сделано (ADR-0028).

## Как сделано в схеме (02.10, фото — 03.10)
- Фото: `recipe_photos` (1:1, кадр 4:3 в пикселях исходника) + `recipe_photo_files` (исходник / `w480` / `w960` /
  `w1600` / `og`, `bytea` `STORAGE EXTERNAL`, ≤ 1 МиБ) — `lib/server/db/schema/photos.ts`, миграция 0007.
- Рецепт: `recipes` (статус, исходный текст, `revision`, основной ингредиент и раздел — отложенные FK, выход —
  дробь) + `recipe_localizations` (slug, название, описание, время, формы выхода; сейчас только ru).
- Количество строки: `exact | range | none` + дроби `amount_num/den` (не float/numeric — ⅓ точна), пометка,
  единица; `none` — только с пометкой. `display_name` — текстом; ссылка на справочник — позже (nullable, expand).
- Разделы и теги состава — таблицы с постоянными id/code и локализациями; связи с порядком (первый — основной).

## Recipe (ТЗ §22)
id · slug · status · title · short_description · main_image (одна фото) · category_id ·
subcategory_id (+ более глубокий уровень при необходимости) · tags[] · servings · cooking_time ·
ingredients[] · primary_ingredient_id · steps[] · nutrition · seo · source_materials[] ·
created_at · updated_at.
- **Одна актуальная версия** (решение владельца): правка меняет сам рецепт, версий/вариаций нет.
- `status`: минимум «черновик» / «опубликован». Публикует только владелец вручную.
- В ТЗ у Recipe есть поле `language`. Предложение: одна запись рецепта + переводы по локалям
  (RU основной, EN производный), а не две независимые записи — иначе расходятся ингредиенты/КБЖУ.
- `source_materials[]` — исходники импорта (текст, аудио, фото, PDF, DOCX, TXT), нужны для
  кнопки «Перегенерировать из исходников».

## RecipeIngredient (ТЗ §8, §22)
ingredient_id (canonical) · display_name · amount · unit · normalized_grams_ml · is_primary ·
comment · kcal_100 · protein_100 · fat_100 · carbs_100.
Примеры из ТЗ: «Творог | 220 | г | основной», «Яйцо | 1 | шт. | ≈ 55 г», «Мука | 50 | г».
- Хранить структурированно, не только текстом.
- `normalized_grams_ml` определяется один раз (при импорте — ИИ, напр. «1 среднее яйцо ≈ 55 г»)
  и **сохраняется**; при открытии страницы заново не вычисляется.
- КБЖУ на 100 г в строке рецепта (по ТЗ) — предложение: брать из справочника ингредиента, в строке
  хранить только переопределение, чтобы правка справочника доезжала до рецептов.

## Уточнения по первому рецепту владельца (02.10, план first-owner-recipe; прототип `app/(admin)/admin/(protected)/ui/_demo/demo-types.ts`)
- **Количество строки** — точное / диапазон («½–1 ч. л.», пересчёт обоих концов) / нет — отдельно от
  **пометки** («по желанию») и единицы (выразимо «зелень — 10 г, по желанию»). Правила: числа > 0, от ≤ до,
  основной ингредиент — только точное число, без количества — обязательно пометка (тест
  `app/(admin)/admin/(protected)/ui/_demo/demo-recipes.test.ts`). В БД — десятичные/дробные числа, не float.
- **Выход** вместо голого `servings`: число + изделие с формами слова («вафля / вафли / вафель», по
  умолчанию «порция») — показ «~ 4 вафли» (ADR-0021: «~ N»). **Необязателен** (владелец 02.10: у вафель
  «абстрактно, зависит от граммов на вафлю») — без выхода число не показывается; **описание** тоже необязательно.
- **Время** — необязательно (владелец: «время не надо»). **Фото** — одно, кадр 4:3 владельца (ADR-0028,
  `lib/server/db/schema/photos.ts`: кадр в пикселях уменьшенного исходника + файлы исходник / WebP 480·960·1600 / OG).
- **Советы** (владелец 02.10, в будущий план): записки к рецепту отдельно от шагов; позже — раздел «Советы».
- **Шаблон текстового файла** (владелец: «загружать рецепт по правильной структуре … текстовым файлом»):
  `Название:`, `Описание:`, `Разделы:` (через запятую, первый — основной), `Время:` (необяз.),
  `Порции:` / выход, `Особенности состава:`, `Ингредиенты:` (строка «название — количество единица»,
  у основного «(основной)», «по желанию»), `Приготовление:` (нумерованные шаги), позже `Советы:`.
  Разбор — кодом (без ИИ), ошибки — по строкам простыми словами (план загрузки).

## Ingredient — справочник (продуктовые решения)
- **Иерархия:** Сыр → Моцарелла, Пармезан, Чеддер, Сливочный сыр; Масло → Сливочное, Оливковое,
  Подсолнечное. В рецепте — максимально конкретный тип, если он влияет на результат.
- Бренды и товарные позиции — не нужны на первом этапе (позже расширяемо).
- Поля (предложение): id, parent_id, name RU/EN, синонимы/словоформы (для поиска и автокомплита),
  КБЖУ на 100 г (усреднённо), эквиваленты единиц (г на шт./ст. л./ч. л./стакан), ссылка на правило
  округления (может наследоваться от родителя: правило «специи» → все специи).

## Единицы (ТЗ §10)
- Базовые для расчётов: граммы, миллилитры, штуки.
- В интерфейсе: кг, г, мл, л, шт., ст. л., ч. л., стакан, щепотка и т. д.
- Условные переводы (щепотка, стакан муки) — сохранённое приближение, не пересчёт ИИ.

## RecipeStep (ТЗ §7, §22)
order · text. Только текст, без обязательных фото шагов.

## Nutrition / КБЖУ (ТЗ §11 + решения)
- kcal, protein, fat, carbohydrates на 100 г (или стандартную единицу) у ингредиента.
- Показывать минимум: всё блюдо и одна порция. Пересчёт математический, без ИИ.
- Ориентировочно: усреднённые значения; явный тип (моцарелла, сливочное масло) считается отдельно;
  жирность и производитель не учитываются.

## Category / Tag
Категории и теги — **разные сущности**. Дерево категорий и теги — `catalog-structure.md`.
У каждой — заранее заданный EN-эквивалент и slug для обеих локалей.

## RoundingRule — таблица правил округления (продуктовые решения)
Поля по решению владельца: можно ли округлять · минимальный шаг · направление (вверх/вниз) ·
допустимое отклонение от пропорции. Содержимое — отдельный этап, см. `rounding-rules.md`.
