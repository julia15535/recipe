# Добавление рецепта и ИИ-импорт (ТЗ §12–17, §23 + продуктовые решения)

## Страница импорта (только владелец после входа)
Главная задача — не заставлять владельца заполнять длинную форму. Любое сочетание источников,
все поля опциональны:
- написать/вставить текст;
- записать аудиосообщение (кнопка записи прямо с телефона);
- фото (страница с рецептом, скриншот, рукописная/печатная запись, если читается);
- PDF; DOC/DOCX; TXT;
- основная фотография готового блюда.
Пример: наговорить рецепт + фото блюда + PDF → «Сформировать рецепт».

## Конвейер
`исходники → извлечение текста → ИИ-структурирование → черновик → предпросмотр → ручная правка → публикация`
- Аудио: `Audio → Speech-to-Text → ИИ-парсер → структура рецепта`. Пример голоса: «Сырники. Беру
  220 граммов творога, одно яйцо, около 40 граммов цельнозерновой муки… Сначала смешиваю…».
- Документы/фото приводятся к единой внутренней структуре рецепта.

## Что определяет ИИ
Название · короткое описание · категория, подкатегория, доп. уровни · подходящие теги · порции ·
время (если указано) · ингредиенты, количества, единицы · основной ингредиент · этапы ·
данные для расчёта КБЖУ (привязка к справочнику ингредиентов, граммовые эквиваленты единиц).
- **Не выдумывать критичные данные**: нет информации — поле пустое.
- **Неуверенные поля выделять** в предпросмотре.
- Категории/теги — выбор из существующих справочников (EN-эквиваленты заданы заранее).
- Результаты ИИ сохраняются структурированно в БД; дальше работает обычная программная логика.

## Предпросмотр (ТЗ §16)
Никакой ИИ-импорт не публикуется автоматически. Предпросмотр — почти как на сайте; редактируемо всё:
название, категория, подкатегория, описание, ингредиенты, количества, основной ингредиент, теги,
порции, этапы, фото, КБЖУ, английская версия.
Кнопки: **Сохранить черновик** · **Опубликовать** · **Перегенерировать из исходников**.

## Публикация (решение владельца)
Опубликованный рецепт = проверенный владельцем. ИИ создаёт только черновик; без ручного
подтверждения не публикуется. Версий нет — правка меняет сам рецепт.

## Английская версия (ТЗ §17)
- Формируется ИИ автоматически при добавлении/редактировании; RU — основная.
- Переводить: название, описание, ингредиенты, комментарии, этапы. Категории/теги — заранее заданные
  EN-эквиваленты.
- Доступна в предпросмотре и правится вручную.

## Где ИИ НЕ используется (ТЗ §23)
Поиск (если хватает индекса), пересчёт порций/ингредиентов/КБЖУ, фильтрация, открытие страницы.

## Концепция питания (решение владельца) — контекст для ИИ
Не строгий ЗОЖ: нормальная домашняя еда с разумным балансом; где не хуже на вкус — меньше сахара,
без лишнего масла, более полезная замена. Вкус важнее диеты.

## Открытые вопросы
- Провайдеры: LLM (структурирование, vision/OCR, перевод) и STT; где ключи — `core/access-and-integrations.md`.
- Новый ингредиент, которого нет в справочнике: ИИ предлагает узел иерархии + усреднённое КБЖУ →
  владелец подтверждает → в справочник (переиспользуется)?
- Правка RU опубликованного рецепта: перегенерировать EN целиком или только изменённые поля
  (не затереть ручные правки EN).
- Предлагать ли в предпросмотре «полезные замены» (меньше сахара/масла) подсказкой, не применяя.
- Хранение исходников (аудио/PDF): сколько и где; удаление после публикации?
