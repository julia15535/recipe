# Source of Truth — доктрина истины

Источники делятся на домены. При конфликте — решаем по приоритету внутри домена; если домены
спорят между собой — фиксируем расхождение явно, не «забалтываем».

## Домен требований — что строим
Приоритет по убыванию:
1. Решения владельца в `decisions.md` (новые ADR отменяют старые явно).
2. Продуктовые решения владельца (новее — важнее): 01.10.2026 — главная и страница рецепта
   (`_intake/_processed/brief/product-decisions-2026-10-01.md`); 27.09.2026 —
   `_intake/_processed/brief/product-decisions.md`.
3. ТЗ «Личная авторская книга рецептов» — `_intake/_processed/brief/technical_spec_recipe_book.md`.

Продуктовые решения **позже ТЗ и уточняют его**; при расхождении побеждают они. Известные
расхождения, разрешённые так:
- Пересчёт: ТЗ §9 — чистое умножение; решения — кулинарно разумно, якорь неизменен, таблица
  правил округления (ADR-0004).
- Аудитория: ТЗ — «преимущественно владелец»; решения — удобно и публичным пользователям.
- Поиск: ТЗ §3 — богатая вложенная фильтрация; решения — сначала простой переключатель
  «По рецепту / По ингредиенту», главное — найти конкретный рецепт (ADR-0002).
- Питание: ТЗ — «преимущественно здоровая еда»; решения — не строгий ЗОЖ, вкус важнее.
- SEO: в MVP по ТЗ, но по приоритету владельца вторично.

## Домен кода — что реализовано
1. Текущий codebase (пока кода нет).
2. `project-state.md` — снимок состояния.
3. `domain/*` — логическая модель (статус `draft` = описано, не реализовано).

## Домен процесса — как работать
1. `.claude/rules/agent-workflow.md` + `guides/agent-workflow.md` — план → «деплой».
2. `.claude/rules/codex-adviser.md` — когда обязателен совет Codex.
3. `.memory_bank/plans/` — активные планы.
4. `guides/code-standards.md`, `guides/review-rules.md`.

**Важно:** код не отменяет процесс. «Код уже написан иначе» — не основание игнорировать workflow.

## Как трактовать конфликты
- Код расходится с требованиями → зафиксировать расхождение, предложить минимальное решение.
- Решение из `decisions.md` устарело → новая ADR-запись, отменяющая старую, а не молчаливый обход.
- Модель пропустила planning step → нарушение процесса, а не оптимизация.

## Невалидные источники (что НЕЛЬЗЯ тащить как шаблон)
- Интерфейс и сложность gotovim-doma.ru — только ориентир классификации каталога.
- Код и доменная логика sup2 — можно подсмотреть технику (вход через Telegram, ИИ-шлюз), но не
  переносить сущности и статусы портала поставщиков.
- Вывод ИИ (черновик рецепта, КБЖУ, перевод) — не истина, пока владелец не подтвердил.
- «Я и так знаю» — не основание пропустить план.
