# Модель данных — Tier 1 сводка

Схема БД ещё не спроектирована — ниже логическая модель из ТЗ §22 и решений владельца.

## Сущности
- **Recipe** — slug, статус (черновик/опубликован), название, описание, одна фото, категория +
  подкатегория (+ глубже), теги, порции, время, ингредиенты, основной ингредиент, шаги, КБЖУ, SEO,
  исходники импорта. **Одна актуальная версия**, без вариаций (ADR-0007).
- **RecipeIngredient** — ингредиент из справочника, отображаемое имя, количество, единица,
  граммы/мл (сохраняются один раз), признак основного, комментарий.
- **Ingredient (справочник)** — иерархия (Сыр → Моцарелла…), КБЖУ на 100 г усреднённо, эквиваленты
  единиц, синонимы, правило округления. Без брендов (ADR-0003).
- **RecipeStep** — порядок + текст.
- **Category** (дерево, ≥3 уровня, редактируемо) и **Tag** — разные сущности; у обеих EN-эквивалент.
- **RoundingRule** — можно ли округлять, шаг, направление, допустимое отклонение (ADR-0004).

## Правила
- Ингредиенты — структурированно, не текстом.
- Всё, что определил ИИ (граммы яйца, категория), сохраняется в БД; при открытии страницы не
  вычисляется заново.
- Переводы: предложение — одна запись рецепта + переводы по локалям (RU основной).
