# Модель данных — Tier 1 сводка

Схема рецептов есть (ADR-0023, `lib/server/db/schema/{recipes,recipe-rows,catalog,photos}.ts`, миграции 0002–0007):
рецепт + локализации, разделы/теги, ингредиенты (дроби), шаги, советы, фото блюда (ADR-0028: `recipe_photos` 1:1 +
файлы `bytea`). Справочника ингредиентов, КБЖУ и EN пока нет — ниже логическая модель целиком.

## Сущности
- **Recipe** — slug, статус (черновик/опубликован), название, описание, одна фото, разделы каталога
  (1+, один основной — ADR-0018) + подкатегории, теги (тематические и «особенности состава» —
  ADR-0019), выход («4 вафли»), описание и время — необязательны, ингредиенты, основной ингредиент
  (якорь пересчёта — если отмечен автором, иначе без пересчёта: ADR-0016, ADR-0025), шаги, советы, SEO, исходники. Количество — точное / диапазон / нет +
  пометка (Tier 2). КБЖУ пока нет. **Одна актуальная версия** (ADR-0007).
- **RecipeIngredient** — ингредиент из справочника, отображаемое имя, количество, единица,
  граммы/мл (сохраняются один раз), признак основного, комментарий.
- **Ingredient (справочник)** — иерархия (Сыр → Моцарелла…), КБЖУ на 100 г усреднённо, эквиваленты
  единиц, синонимы, правило округления. Без брендов (ADR-0003).
- **RecipeStep** — порядок + текст.
- **Category** (дерево, ≥3 уровня, редактируемо; стабильный ID, slug по языкам + история → 301,
  ADR-0017; рецепт ↔ категория — многие-ко-многим) и **Tag** (группа: тематический / состав) —
  разные сущности; у обеих EN-эквивалент.
- **RoundingRule** — шаг, направление, отклонение (ADR-0004; сейчас правила в коде — ADR-0026).

## Правила
- Ингредиенты — структурированно, не текстом.
- Определённое ИИ сохраняется в БД, при открытии страницы не вычисляется заново.
- Переводы — одна запись рецепта + локализации (RU основной).
