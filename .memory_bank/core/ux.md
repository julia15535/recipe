# UX и mobile-first — Tier 1 сводка

## Принципы (ТЗ §1, §21)
- Mobile-first — принципиально. Минимум лишнего, максимально быстрая навигация.
- Одной рукой: найти, открыть, вписать своё количество, переключить вкладки, надиктовать рецепт,
  загрузить фото, проверить черновик, опубликовать. Без мелких элементов и desktop-dropdown.
- Визуально: домашняя, современная, преимущественно полезная еда (не строгий ЗОЖ).

## Экраны (решения владельца 01.10; детали — Tier 2)
- **Шапка** = название · лупа · язык + каталог, закреплена (`components/site-header.tsx`); каталог: компьютер —
  лента из 11 мест (пустые бледные и не ссылки, ADR-0020), телефон — «меню» слева. Кнопки языка пока нет (ADR-0027).
- **Главная** (ADR-0027): каталог в шапке + «Новые рецепты» (до 12); «Подборка недели», «Популярное» — позже.
- **Раздел:** сразу рецепты раздела, без поиска; текущий раздел выделен в каталоге.
- **Поиск:** отдельная страница, на компьютере — карточкой по центру.
- **Рецепт:** строка «время (если задано) + цветные теги состава» (ADR-0021), вкладки «Рецепт / Приготовление»,
  «~ N порций» (или «~ 4 вафли»; если выход задан), своё количество основного ингредиента — если автор его отметил (ADR-0016, ADR-0025); КБЖУ пока нет (ADR-0019).
- Прототипы `/admin/ui` (вход владельца) — на тех же компонентах; сайт — `e2e/public.spec.ts`.

## Критерии успеха (решение владельца, по порядку)
1. Очень быстро найти рецепт. 2. Удобно пользоваться во время готовки. 3. Очень быстро добавлять.
4. Удобно делиться. SEO — вторично.

## Открыто
«Удобно у плиты» (экран не гаснет, крупный шрифт?) и «удобно делиться» («Поделиться») — с владельцем.
