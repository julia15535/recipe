# Пересчёт рецепта — Tier 1 сводка

## Суть (ADR-0004; режим — ADR-0016)
- Якорь — **основной ингредиент** (обязателен у каждого рецепта; ИИ предлагает, владелец подтверждает):
  посетитель вписывает своё количество в его единице (г, шт., мл), кнопок «−/+» порций нет.
  Коэффициент = новое / базовое (творог 500 → 250 г = ×0,5); порции производные, дробные допустимы.
- Отменено владельцем 01.10: режим «по порциям» и якорь — любой ингредиент.
- **Кулинарно разумно**, не только математически.
- **Якорь неизменен:** введённое пользователем остаётся ровно; остальное — от него.
- Неудобные значения (яйцо = 1,4 шт.) — по **таблице правил округления по типу ингредиента**:
  можно ли округлять, минимальный шаг, вверх/вниз, допустимое отклонение пропорции.
- Ориентиры владельца: яйца — до целых по отдельному правилу; сахар и соль — чаще вниз; специи — до
  практичных мер; мясо, творог, мука — введённое не менять. Исследование «как принято» и предложение
  таблицы v1 (01.10, ждёт утверждения) — в Tier 2.

## Правила
- Пересчёт — программно, мгновенно, без ИИ. КБЖУ пока не считаем (ADR-0019).
- Правила округления — в таблице БД, применяются кодом; ИИ не решает каждый раз.
- **Порядок работ:** таблицу правил проработать **отдельным этапом ДО реализации пересчёта**
  (нормы предметной области → разбор с Codex и источниками). До него пересчёт есть только в
  прототипе — точное умножение без кулинарного округления (на экран — до десятых, меньше 1 — две значащие цифры) (`app/(admin)/admin/ui/_demo/demo-rescale.ts`, тест рядом; e2e — `e2e/prototypes.spec.ts`).
