# Загрузка рецепта текстом — Tier 1 сводка (ADR-0023)

## Как работает
- Кабинет `/admin` → «Мои рецепты» → «Добавить рецепт» (`app/(admin)/admin/(protected)/recipes/new/page.tsx`):
  вставить текст как пишет владелец → «Проверить» → предпросмотр как на сайте + «Что поправить» (номер
  строки, сама строка, простое объяснение) → «Сохранить черновик» / «Опубликовать».
- Правка — «Изменить»: тот же текст в поле, сохраняется новой версией целиком; адрес и статус не меняются;
  устаревшая вкладка получает «Рецепт уже изменён в другой вкладке» (`revision` — `lib/server/recipes/save.ts`,
  текст — `app/(admin)/admin/(protected)/recipes/actions.ts`); сбой БД — сообщение, текст в поле остаётся.
- «Опубликовать» / «Снять с публикации»; удалить можно только черновик. Публичных страниц пока нет —
  опубликованное появится на сайте со следующим планом.

## Правила разбора (без ИИ, `lib/domain/recipe-text/parse.ts`)
- Понимает стиль вафель: «Теги: завтрак, белок» (раздел + тег), «— основной ингредиент», «(по желанию)»,
  «щепотка», «½–1 ч. л.», «1ст л». Основной ингредиент отмечает владелец — без пометки сохранить нельзя.
- У ингредиента — количество или явная пометка без числа («по вкусу», «по желанию», «щепотка»…, можно в
  скобках); непонятная строка — ошибка, не пропадает.
- Количества — точные дроби (⅓ остаётся ⅓): `lib/domain/fraction.ts`, пересчёт — `lib/domain/rescale.ts`.

## Хранение
Таблицы рецептов, локализаций, разделов и тегов — миграции 0002/0003; сервер сохраняет только то, что сам
разобрал из текста; каждое действие и страница — `requireOwner()`.
