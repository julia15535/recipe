# Решения ADR-0001…0050 — полные тексты

> Индекс, «по темам» и как читать — `../decisions.md`. Новое решение: текст — сюда (пока номера ≤ 0050),
> строка — в индекс. Тексты перенесены дословно из `decisions.md` 02.10.2026.

## ADR-0001 — 2026-09-27 — Каталог по типу блюда; категории и теги — разные сущности
**Решение:** основная классификация — по типу блюда, 10 верхних категорий (закуски, салаты, супы,
вторые блюда, выпечка, десерты, напитки, соусы, заготовки, разное) с подкатегориями по мотивам
gotovim-doma (глубина до 3+). Теги — отдельная сущность. Структура редактируется из админки.
**Почему:** ТЗ §2, §4–5 и продуктовые решения: ингредиенты не являются структурой каталога.
**Альтернативы:** каталог по ингредиентам — отвергнут владельцем; копия интерфейса gotovim-doma —
запрещена ТЗ (только ориентир классификации).
**Влияет на:** `core/catalog.md`, `domain/catalog-structure.md`, модель данных, SEO-страницы.

## ADR-0002 — 2026-09-27 — Поиск: переключатель «По рецепту / По ингредиенту» с иерархией, без ИИ
**Решение:** на главной — переключатель режимов; по ингредиенту — один или несколько (И),
родитель находит потомков («сыр» → моцарелла…), конкретный тип — только себя; уточнение
категорией/тегом; автокомплит; без огромного каталога ингредиентов на главной; без ИИ.
**Почему:** приоритет №1 — максимально быстро найти конкретный рецепт, особенно с телефона.
**Альтернативы:** ИИ-поиск — избыточен при индексе (ТЗ §3, §23); «что приготовить из того, что
есть» как главный сценарий — отвергнут владельцем.
**Влияет на:** `core/search.md`, `domain/search-spec.md`, справочник ингредиентов, главная.

## ADR-0003 — 2026-09-27 — Иерархический справочник ингредиентов без брендов
**Решение:** ингредиенты — справочник с иерархией (Сыр → Моцарелла; Масло → Оливковое); в рецепте
— максимально конкретный тип, если он важен для результата; бренды и товары не храним.
**Почему:** нужно для поиска по иерархии и отдельного КБЖУ явных типов (продуктовые решения).
**Альтернативы:** плоский список / текст ингредиентов — не даёт иерархического поиска и КБЖУ;
товарные позиции — позже, как расширение.
**Влияет на:** `core/ingredients.md`, модель данных, поиск, КБЖУ, правила округления.

## ADR-0004 — 2026-09-27 — Пересчёт: неизменяемый якорь + таблица правил округления
**Решение:** коэффициент считается от якоря (порции или количество ингредиента, введённое
пользователем); якорь не меняется; остальные значения округляются по таблице правил по типу
ингредиента (можно ли, шаг, вверх/вниз, допустимое отклонение). Правила — в БД, применяются кодом;
проработать отдельным этапом ДО реализации пересчёта.
**Почему:** пересчёт должен быть кулинарно разумным (яйцо 1,4 шт. — неприемлемо), а не только
математическим; ИИ не должен решать округление каждый раз.
**Альтернативы:** чистое умножение (ТЗ §9) — уточнено владельцем; единое правило округления —
отвергнуто; ИИ на каждом пересчёте — запрещён ТЗ §9.
**Влияет на:** `core/rescaling.md`, `domain/rounding-rules.md`, КБЖУ, страница рецепта.

## ADR-0005 — 2026-09-27 — КБЖУ ориентировочно по усреднённым значениям
**Решение:** КБЖУ на 100 г хранится у типа ингредиента (усреднённо), без бренда, упаковки и точной
жирности; явный тип (моцарелла, сливочное масло) — свои значения; блюдо и порция считаются
математически при каждом пересчёте.
**Почему:** первый этап — ориентир, не диетология; вкус важнее строгих принципов.
**Альтернативы:** точные данные по продуктам/брендам — позже; ИИ-расчёт КБЖУ на лету — запрещён.
**Влияет на:** `core/ingredients.md`, модель данных, страница рецепта.

## ADR-0006 — 2026-09-27 — Публикует только владелец; ИИ создаёт только черновик
**Решение:** любой ИИ-импорт → черновик → предпросмотр → ручная правка → публикация владельцем.
Опубликованный рецепт считается проверенным владельцем.
**Почему:** ТЗ §16 и продуктовые решения — без ручного подтверждения рецепт не публикуется.
**Альтернативы:** автопубликация уверенных импортов — отвергнута.
**Влияет на:** `core/recipe-import.md`, `core/auth-publishing.md`, статусы рецепта.

## ADR-0007 — 2026-09-27 — Одна актуальная версия рецепта
**Решение:** версий и вариаций рецепта нет; правка меняет сам рецепт.
**Почему:** продуктовые решения владельца — отдельные версии не нужны.
**Альтернативы:** история версий / варианты рецепта — отвергнуты.
**Влияет на:** модель данных (без таблиц версий), админка.

## ADR-0008 — 2026-09-27 — ИИ только на входе данных; дальше — обычный код
**Решение:** ИИ: распознавание текста/голоса/изображений/PDF/Word, структурирование, первичные
категория/теги/основной ингредиент, нормализация неоднозначных единиц, перевод RU→EN. Не ИИ:
поиск, фильтрация, пересчёт порций/ингредиентов/КБЖУ, открытие страницы. Результаты ИИ
сохраняются структурированно в БД.
**Почему:** ТЗ §23 — скорость, предсказуемость, стоимость.
**Альтернативы:** ИИ в рантайме страниц/поиска — отвергнуто.
**Влияет на:** `core/architecture.md`, `core/recipe-import.md`, все расчёты.

## ADR-0009 — 2026-09-27 — RU основной, EN — автоперевод ИИ с ручной правкой
**Решение:** RU — основная версия; EN формируется ИИ при добавлении/правке, доступна в
предпросмотре и правится вручную; категории/теги — заранее заданные EN-эквиваленты; URL
`/ru/…` и `/en/…`.
**Почему:** ТЗ §17, §19 — две индексируемые языковые версии.
**Альтернативы:** ручной перевод — медленно; машинный перевод на лету — не индексируется и
нестабилен.
**Влияет на:** `core/seo-i18n.md`, модель данных (переводы), импорт.

## ADR-0010 — 2026-09-27 — Вход владельца: телефон → подтверждение в Telegram
**Решение:** админ-функции — одному/нескольким владельцам; вход по номеру телефона с
подтверждением через Telegram; посетители без аккаунтов (чтение, поиск, пересчёт, язык).
**Почему:** ТЗ §18; у владельца есть отработанная схема в sup2 (решение D10).
**Альтернативы:** email/пароль, OAuth — не требуются ТЗ.
**Влияет на:** `core/auth-publishing.md`, `core/access-and-integrations.md` (Telegram-бот).
**Статус:** телефон и схема sup2 отменены ADR-0022 (вход — через своего бота с подтверждением кодом).

## ADR-0011 — 2026-09-29 — Стек: Next.js 16.3 + TypeScript 6 + Drizzle/Postgres, две ветки маршрутов
**Решение:** Node 24 LTS, pnpm 12 (точная версия в `packageManager`), Next.js 16.3 App Router
(`output: "standalone"`), React 19, TypeScript 6.0 (`strict`, `noUncheckedIndexedAccess`), ESLint 9
flat на `eslint-config-next` (`eslint.config.mjs`), Tailwind 4 + shadcn/ui base-nova (заменено ADR-0015),
Zod 4, next-intl 4, Vitest 4 + Playwright. Маршруты: `app/(public)/[locale]` (ru/en, `localePrefix:
"always"`, `/` → язык браузера или `/ru`) и `app/(admin)/admin` (только RU, `noindex`) с отдельными root
layout; один `proxy.ts`. Слои: `lib/domain` — чистые функции без IO (запрет импортов — ESLint),
`lib/server` — `server-only` (БД, env, логгер). Env: публичная конфигурация запекается при сборке,
секреты читаются лениво; в production без них — явная ошибка при старте (`instrumentation-node.ts`,
разбор — `lib/server/env-schema.ts`, тест `lib/server/env.test.ts`).
**Почему:** стек владельца из sup2/sib с поправками по их граблям; критика Codex 27.09 (33 замечания).
**Альтернативы:** TS 7 — не поддерживается typescript-eslint 8.70 (peer `<6.1`); ESLint 10 / Vitest 5 —
плагины не проверены; Node 22 — EOL 04.2027; `localePrefix: "as-needed"` — противоречит ADR-0009;
Astro/Payload — отдельный рантайм или готовая админка не нужны.
**Влияет на:** весь код, `.claude/rules/code-standards.md`, `.claude/rules/ui-rules.md`, `core/architecture.md`.

## ADR-0012 — 2026-09-29 — БД и миграции: Drizzle generate + прод-мигратор с блокировкой, три роли
**Решение:** PostgreSQL 17, Drizzle ORM + postgres.js. Миграции: `drizzle-kit generate` → ревью SQL →
в проде `node migrator/migrate.mjs` (сборка `scripts/migrate.mjs`: session advisory lock, `SET ROLE
recipe_owner`; тест `scripts/db.test.ts`). `drizzle-kit push` в проде запрещён; порядок журнала проверяет
`scripts/check-migrations.mjs`. Схема меняется только expand → код → backfill → contract. Роли
(`deploy/recipe-roles.sql`): `recipe_owner` (NOLOGIN, владелец схемы), `recipe_migrator` (логин
миграций), `recipe_app` (рантайм, только DML); таймауты на ролях; веб не получает миграционный доступ.
**Почему:** в standalone-образе нет drizzle-kit; откат образа не откатывает схему; компрометация сайта
не должна давать DDL. Критика Codex 29.09.
**Альтернативы:** идемпотентный raw SQL (remlab) — второй источник истины рядом со схемой Drizzle;
одна роль на всё (sup2) — лишние права у веба.
**Влияет на:** `lib/server/db/*`, `drizzle/`, `deploy/recipe-deploy.sh`, CI, план «схема БД».

## ADR-0013 — 2026-09-29 — Кэш публичных страниц: Cache Components с тегами
**Решение:** `cacheComponents: true`, `"use cache"` + `cacheTag`; теги `recipe:{id}`, `recipes`,
`category:{id}`, `tag:{id}`, `catalog`; правка владельцем → `updateTag` (обе локали, старый и новый
slug, списки). **Проверено на каркасе (29.09):** совместимо с next-intl 4.14 через `next/root-params`
(`i18n/request.ts`) — `/ru`, `/en` собираются статически (`next build`: ○), без `setRequestLocale`;
`dynamicParams` при cacheComponents не экспортировать; `headers()`/`cookies()` в `i18n/request.ts` не
читать (сделает страницы динамическими). Прокси ставит cookie `NEXT_LOCALE` и на статических ответах —
при кэширующем CDN такие ответы не кэшировать.
**Почему:** модель кэша Next 16 определяет, как пишутся все страницы — выбирать до доменного кода.
**Альтернативы:** классический ISR — запасной путь; кэш без тегов — нет точечной инвалидации.
**Влияет на:** страницы каталога и рецепта, админку (инвалидация).

## ADR-0014 — 2026-09-29 — CI/CD: один образ из CI в GHCR, сервер сам забирает (модель sup2)
**Решение:** GitHub Actions (`.github/workflows/ci.yml`) собирает образ один раз, гоняет на нём миграции
и e2e, публикует `ghcr.io/julia15535/recipe:<sha>` и `:stable` (только текущий HEAD `main`, только при
изменении кода). Сервер: `recipe-deploy.timer` каждые 5 минут → `deploy/recipe-deploy.sh`: точка отката
до pull → миграция одноразовым контейнером → кандидат во внутренней сети → swap → smoke по SHA; упала
миграция — прод на прежней версии; кандидат не поднялся — карантин образа; smoke после swap — откат
(при нужде pull из GHCR) и карантин (`deploy/README.md`); `KillMode=process`, `9>&-` (грабли sup2). Контейнеры с лимитами CPU/RAM
и OOM-приоритетом, read-only, без capabilities. Бэкап: `pg_dump -Fc` раз в сутки на сервере ≤ 7 дней
(`deploy/recipe-db-backup.sh`) + локальная копия владельца ≤ 7 дней и еженедельное восстановление
(`deploy/local/`). Детали сервера — только `_secrets/ACCESS.md` (репо публичный).
**Почему:** просьба владельца «CI/CD как в sup2»; 1 vCPU сервера делится с соседними сервисами —
сборка на сервере недопустима; pull-модель не требует секретов в GitHub. Критика Codex 29.09 (35
замечаний: digest вместо тега, откат до pull, карантин, раздельные env).
**Альтернативы:** сборка на сервере (sup2) — отнимает CPU у соседей; push-деплой по SSH из Actions —
долгоживущий ключ к общему серверу в GitHub; `paths-ignore` — оставляет обязательную проверку висеть.
**Влияет на:** `Dockerfile`, `deploy/`, `.github/`, `core/deployment.md`.

## ADR-0015 — 2026-09-29 — Дизайн-система Untitled UI React и своя палитра «олива + персик» (отменяет UI-часть ADR-0011)
**Решение:** интерфейс — Untitled UI React (Tailwind 4 + React Aria), бесплатная MIT-часть, копия из
upstream github.com/untitleduico/react @ `4702dc0ea8d1` в `components/base|application|foundations`,
`styles/uui/*` (список и изменения — `THIRD_PARTY_NOTICES.md`). Бренд — только `styles/brand.css`:
главный цвет — олива (600 `#617122`), акцент — персик/абрикос (`accent-*`, 100 `#ffeadb`, 700
`#8b5426`), тёплые нейтрали, фон — кремовая «бумага» `#f8f2e6`, карточки — светлый крем `#fefcf6`,
основной текст — тёплый графит `#36322d`; шрифты — заголовки Prata (с засечками, одно начертание 400,
«нарисованный» жирный запрещён `font-synthesis: none`), текст Manrope через `next/font` (`styles/fonts.ts`). Кнопки — `AppButton` (`components/app-button.tsx`):
размер `xl` = 48 px (не меньше 44 по ТЗ), форма «таблетка». Ссылки-кнопки — `components/providers/public-router-provider.tsx` (префикс
локали next-intl) и `admin-router-provider.tsx`. Иконки — Lucide.
**Решение владельца 30.09:** оставить оливу, добавить персик, кремовый фон вместо белого, графитовый
текст вместо чёрного, заголовки с засечками. Просили Fraunces — в нём нет кириллицы (русские заголовки
показались бы случайным запасным шрифтом) → на пробной странице сравнили Lora/Literata/Alegreya, затем
владелец выбрала Prata (заголовки) и Manrope (текст).
**Почему:** решение владельца (29.09): система как в соседнем remlab, но из исходника upstream, без
цветов и доработок remlab; палитра с нуля, тёплая, для еды; ориентир стиля — sallysbakingaddiction.com
(фото-карточки, таблетки, пастель, дружелюбные заголовки). Контраст — WCAG AA (axe в `e2e/design.spec.ts`).
**Альтернативы:** остаться на shadcn base-nova — владелец выбрал UUI; копировать remlab — запрещено
владельцем; иконки `@untitledui/icons` — их лицензия запрещает распространение (npm пишет MIT —
противоречие), репо публичный; PRO — нельзя публиковать.
**Влияет на:** `styles/**`, `components/**`, `app/**` (все страницы), `.claude/rules/ui-rules.md`,
`THIRD_PARTY_NOTICES.md`, `e2e/design.spec.ts`.

## ADR-0016 — 2026-10-01 — Пересчёт от одного основного ингредиента, порции производные (меняет режимы ADR-0004)
**Решение:** у каждого рецепта ровно один основной ингредиент (ИИ предлагает при импорте, владелец
подтверждает) — он и есть якорь пересчёта. Посетитель вписывает его количество в его же единице
(г, шт., мл; поле ввода, без «−/+»), коэффициент = новое / базовое; остальные ингредиенты и число
порций — от коэффициента, порции дробные допустимы («2,5 порции»). Режимы «по порциям» и «якорь —
любой ингредиент» из ADR-0004 отменены; неизменяемость якоря и таблица правил округления ДО
настоящего пересчёта — остаются. До этапа округления пересчёт есть только в прототипе
(`app/(admin)/admin/(protected)/ui/_demo/demo-rescale.ts` — точное умножение, без округления, с подписью «пример»).
**Почему:** продуктовые решения владельца 01.10 (выше ТЗ по `source-of-truth.md`):
калькулятор порций «−/+» убрать, граммы вписывать у основного ингредиента.
**Альтернативы:** «−/+» порций — отвергнуто владельцем; якорь — любой ингредиент — сложнее и не
просили; рецепты без граммового якоря не пересчитывать — отвергнуто (основной в своей единице).
**Влияет на:** `core/rescaling.md`, `domain/rounding-rules.md`, `core/data-models.md`, страница рецепта,
ИИ-импорт.

## ADR-0017 — 2026-10-01 — URL каталога: плоский `/{locale}/catalog/{slug}`, slug по языкам
**Решение:** страница раздела/подраздела — `/{locale}/catalog/{slug}` независимо от глубины дерева
(иерархия — хлебными крошками, перенос подраздела не меняет адрес); slug свой у каждого языка, у
категории стабильный ID, история старых slug → 301; переключение языка — через ID категории, не
заменой строки. Адрес рецепта не зависит от раздела. Поиск — отдельная страница `/{locale}/search`,
состояние в адресе, всегда `noindex`. Реализация — в плане схемы БД; страниц-заглушек не делаем.
**Почему:** ADR-0001 (дерево до 3+ уровней, правка и объединение из админки) + SEO на двух языках;
критика Codex 01.10.
**Альтернативы:** `/ru/salaty` — засоряет корень, конфликты с рецептами и служебными страницами;
`/ru/c/salads` — один английский slug, непонятно человеку; вложенные `/catalog/salaty/klassicheskie` —
перенос ветки ломает адреса.
**Влияет на:** `core/seo-i18n.md`, `core/catalog.md`, схема БД, `i18n/*`, sitemap.

## ADR-0018 — 2026-10-01 — 11 верхних разделов каталога; рецепт в нескольких разделах, один основной (частично отменяет ADR-0001)
**Решение:** верхние разделы: Завтраки · Супы · Салаты · Горячее · Гарниры · Закуски · Выпечка ·
Десерты · Соусы · Напитки · Заготовки («Вторые блюда» → «Горячее»; «Завтраки» и «Гарниры» — новые;
«Разное» убрано, его подкатегории разносятся). Рецепт связан с одним или несколькими разделами
(многие-ко-многим), один — основной (хлебные крошки, порядок). Разделы показываются на главной
(лента на компьютере, нижний лист на телефоне) и на странице рецепта — спокойной строкой ссылок
(«Завтраки · Выпечка»). Тематические теги («На скорую руку», «Постное») остаются отдельной
сущностью — для поиска и фильтров, на рецепте не видны. Дерево по-прежнему правится из админки.
**Почему:** владелец 01.10: «Метки нужны, но типа: Завтраки · Супы · …» + «все как советуешь»
(список = разделы каталога; несколько разделов; «Заготовки» оставить, «Разное» убрать).
**Альтернативы:** один раздел + теги — плохо выдерживает «Сырники → Завтраки + Выпечка»; убрать
«Заготовки» — соленья/заморозку честно некуда разнести; скрыть «Разное» в базе — второй невидимый каталог.
**Влияет на:** `core/catalog.md`, `domain/catalog-structure.md`, `core/data-models.md`, `core/search.md`,
главная и страница рецепта, ИИ-импорт (предлагает разделы).

**Влияет на:** `core/catalog.md`, `domain/catalog-structure.md`, `core/search.md`, `core/ux.md`,

## ADR-0020 — 2026-10-01 — Каталог: 11 постоянных мест, пустой раздел бледный и не нажимается (дополняет ADR-0018)
**Решение:** лента (компьютер) и нижний лист (телефон) всегда показывают все 11 разделов в постоянном
порядке. Раздел без опубликованных рецептов (с учётом подразделов) — не ссылка, а текст: бледные значок
и название (контраст названия ≥ 4,5 : 1), пометка «пока нет рецептов» (в листе — видимая строка); с первым рецептом
раздел «оживает» и становится ссылкой. Нет рецептов совсем — все места бледные, на главной «Скоро здесь
появятся рецепты», подборки скрыты. В уточнении поиска — только непустые разделы (нет — группы нет;
`?section=` пустого раздела не применяется, показывается пояснение «пока пуст»).
**Почему:** владелец 01.10: «иконочки … будут появляться по мере того, как появится рецепт … даём им
место», выбран вариант «Б: все 11 мест на ленте видны сразу, пустые разделы бледные и не нажимаются».
**Альтернативы:** А — пустых значков нет совсем — владелец выбрала Б; пустые как disabled-ссылки —
семантически хуже статуса и прячут низкий контраст от axe (критика Codex 01.10).
**Влияет на:** `components/catalog/*`, `core/catalog.md`, `core/ux.md`, поиск; публичная часть — признак
«пустой» из БД и сброс кэша при публикации/снятии/переносе рецепта (план схемы/каталога).

## ADR-0021 — 2026-10-01 — Рецепт: строка «время + теги состава своим цветом», «~ N порций» у ингредиентов (меняет показ из ADR-0019)
**Решение:** в шапке рецепта одна строка: значок часов и время, рядом теги «Особенности состава», у
каждого свой цвет по ассоциации (Белок — персик, Клетчатка — олива, Полезные жиры — золото, Мало
сахара — пыльно-голубой, Железо — ягодный; токены `--color-tag-*` в `styles/brand.css`, ключ — стабильный
id тега, не подпись); заголовка блока и подписи «Отмечено автором… не расчёт КБЖУ» нет (у группы — только
доступное имя «Особенности состава»). Порции — «~ N порций» справа от заголовка «Ингредиенты»
(диктору — «примерно»), карточки и правой колонки нет; на компьютере рецепт — одна колонка.

**Альтернативы:** один цвет для всех тегов (Codex) — владелец выбрала свои цвета; скрытая подпись для
экранного диктора — дисклеймер только для части посетителей, отвергнуто. Риск: без подписи теги
читаются как обещание пользы — при рекламе/партнёрских продуктах пересмотреть (ADR-0019).
**Влияет на:** страница рецепта, `styles/brand.css`, `core/ux.md`, `domain/catalog-structure.md`.

## ADR-0022 — 2026-10-02 — Вход владельца: свой Telegram-бот с подтверждением кодом, сессии в Postgres, строгая CSP кабинета (частично отменяет ADR-0010)
**Решение:** без телефона и без Telegram Login Widget. «Войти через Telegram» (POST) создаёт попытку:
challenge и привязка браузера по 256 бит + код из 4 цифр, 10 минут; в БД только SHA-256. Ссылка
`t.me/<бот>?start=<challenge>` (и QR для компьютера); бот на `/start` присылает код и кнопки
«Подтвердить» / «Это не я»; подтверждает только кнопка от `OWNER_TELEGRAM_ID` в личном чате. Вкладка
опрашивает статус по cookie привязки и сама получает новую сессию (30 дней, без продления, в БД хеш);
`requireOwner()` в каждой закрытой странице и действии; весь `/admin`, включая пробные экраны, закрыт,
кроме `/admin/login`. Webhook с секретным заголовком, повтор `update_id` не действует. `/admin` —
полностью динамический с CSP на nonce.
**Почему:** владелец 02.10: «как сделать подключение по телеграму», бот и id готовы; Login Widget у
Telegram в архиве (новый — OIDC, сложнее и с внешними скриптами); телефон одному владельцу не нужен.
Подтверждение кнопкой с кодом на экране закрывает подсунутую ссылку (login CSRF, критика Codex).
**Альтернативы:** телефон + код (sup2 D10) — лишний шаг; Login Widget / OIDC — архив или сложность;
вход сразу по `/start` — уязвим к подсунутой ссылке; JWT без БД — нельзя отозвать сессию.
**Влияет на:** `core/auth-publishing.md`, `domain/owner-auth.md`, `core/architecture.md`,
`core/access-and-integrations.md`, `core/deployment.md`, `deploy/README.md` (аварийная памятка).

## ADR-0023 — 2026-10-02 — Рецепт добавляется вставкой текста «как пишет владелец»; схема рецептов: точные дроби, локализации, каталог в БД
**Решение:** в кабинете — поле «Вставьте текст рецепта» → «Проверить» → предпросмотр как на сайте и «Что
поправить» (номер строки, код замечания) → черновик / опубликовать; правка — новая версия текста целиком

должен быть отмечен (сайт не выбирает сам); сохранение заново разбирает текст на сервере. Количества —

сначала кабинет, без фото, правка = загрузить заново. Критика Codex: ⅓ в numeric неточна; частичный UNIQUE не

ломает ADR-0017.
**Альтернативы:** строгий шаблон (любая опечатка — ошибка), ИИ-разбор (платно, ADR-0008 — позже), PDF/Word
(чуть дольше), правка по полям (дольше); numeric для количеств, справочники каталога в коде, `is_main`.
**Влияет на:** `core/recipe-import.md`, `domain/recipe-upload.md`, `core/data-models.md`,
`domain/recipe-model.md`, `core/catalog.md`, `core/architecture.md`.

## ADR-0024 — 2026-10-02 — Рецепт из любого текста разбирает ИИ (Vercel AI Gateway, openai/gpt-6-luna); разбор без ИИ — запасной путь (меняет часть ADR-0023)
**Решение:** «Добавить рецепт» → вставить как есть → «Разобрать»: ИИ через Vercel AI Gateway (`json_schema strict`,
модель `openai/gpt-6-luna`, `reasoning_effort: low`) раскладывает по полям и шагам; ответ проверяет код
(`lib/domain/recipe-text/from-ai.ts`) и показывает «Проверьте»: нужно решить / что сделал ИИ (цитаты из текста
сверяются) / замечания. Разбор хранится на сервере (`recipe_imports`, сутки), сохранение берёт его по id;
`source_text` — аккуратный текст нашего формата (для «Изменить»), `original_text` — вставленный как есть; советы
сохраняются (`recipe_tips`). Сбой ИИ → «Разобрать по старому формату» (детерминированный разбор ADR-0023).
Ключ шлюза — из соседнего проекта sup2 (общий расход), лимит 30 разборов в час, один за раз.
**Почему:** владелец 02.10: «Ты чё заставляешь меня на шаги делить?… я тебе кидаю хоть какой текст… ты его
разбивай… и мне показываешь на проверку», ключ sup2 — её разрешение. ADR-0008 разрешает ИИ на входе.
Замер 12 текстов: выдуманных чисел нет, ~$0.0006 и 1–8 с на рецепт; дешевле и бережнее к словам автора, чем
gpt-5.6-luna и deepseek-v4-flash; gemini-3.1-flash-lite не принял схему (nullable object).
**Альтернативы:** только детерминированный разбор (владелец отвергла), ИИ → текст → разбор при сохранении
(Codex: хрупкий круг; оставлен лишь для «Изменить»), автоповторы запросов (могут стоить денег — повторяет она).
**Влияет на:** `core/recipe-upload.md`, `domain/recipe-upload.md`, `core/access-and-integrations.md`,
`core/architecture.md`, `core/deployment.md`, `deploy/README.md`.

## ADR-0025 — 2026-10-02 — Основной ингредиент — только отмеченный автором; без него и без количеств рецепт сохраняется без пересчёта (меняет часть ADR-0016)
**Решение:** основной ингредиент (якорь пересчёта) есть, только если владелец сама отметила его в тексте
(«основной»); ИИ его не выбирает, а отмеченный ИИ сверяется с текстом (пометка в той же строке, что и
ингредиент). Не отмечен — рецепт сохраняется без пересчёта (`recipes.main_ingredient_id` может быть NULL,
миграция 0005; на странице нет поля «своё количество»). Ингредиент без количества и пометки допустим —
строка без числа (CHECK, миграция 0006). Примерный вес в скобках рядом с ложками/стаканами/штуками
(«1 ч. л. (примерно 3 г)») и повтор количества («280 г (280 г)») не показываются — граммы в пометке не
пересчитываются (`lib/domain/recipe-text/notes.ts`); ложки в граммы не переводятся.
**Почему:** владелец 02.10 после пробы морковного кекса (ИИ выбирал основным то муку, то морковь): «если я
отметила, то он есть, если не отметила, то его нет»; «сохранять без пересчёта»; «только ложки»; «если я пишу
1 ч. л. не нужно переводить в граммы, пиши как я написала». Совет Codex: отмеченный ИИ основной сверять с текстом.
**Альтернативы:** ИИ выбирает по правилу (продукт из названия / самый тяжёлый) — владелец отвергла; без основного
не сохранять — отвергла; показывать и граммы — путаница при пересчёте.
**Влияет на:** `core/rescaling.md`, `core/recipe-upload.md`, `domain/recipe-upload.md`, `core/data-models.md`,
`lib/domain/recipe-text/{parse,from-ai,notes}.ts`, `lib/server/ai/recipe-prompt.ts`.

## ADR-0026 — 2026-10-02 — Округление пересчёта: к ближайшей удобной мере (USDA/NFSMI), яйца граммами при большом отклонении (King Arthur), значок ≈ (меняет часть ADR-0004 и решений 02.10)
**Решение:** точный пересчёт хранится, округляется только показ (`lib/domain/rounding.ts`): всё — к ближайшему
(не вверх/вниз); граммы и мл — до 1, от 1000 — кг/л до сотых; ч. л. — до ¼, меньше ⅛ — «щепотка»; ст. л. — целыми
и половинками, при отклонении > 15 % — в ч. л.; стаканы — до ¼; штучное — до ½ при отклонении ≤ 25 %, иначе до
десятых; яйца («яйцо/яйца» в шт.) — целые при отклонении ≤ 15 %, иначе граммами (1 яйцо ≈ 50 г, «слегка
перемешайте яйца и отвесьте»); желток, белок, порошок — не как яйца; «для смазки» — без пересчёта; диапазон —
оба конца в одной единице. ≈ — у всех пересчитанных строк (коэффициент ≠ 1), кроме основного ингредиента.
**Почему:** владелец 02.10: «почему при пересчёте он всё равно пишет 2,2 яйца?», «найди источник крутой
кулинарный авторитетный… и решим по нему», ≈ — «Да». Источники: USDA FNS + National Food Service Management
Institute, «Measuring Success with Standardized Recipes» (2002), Appendix D Rounding Rules (принцип «ближайшая
удобная мера»; шаги у USDA мельче — упрощены для дома); King Arthur Baking «How to reduce a recipe» (2020): яйцо
≈ 50 г, часть яйца — отвесить. Критика Codex: честно описать упрощение, яйца граммами при большом отклонении.
**Альтернативы:** прежние «сахар вниз / молоко вверх» (источник — к ближайшему); шаги USDA как есть (¼ ч. л. для
всего меньше 2 ст. л. — неудобно дома: «3¼ ч. л. молока»); половинки яиц (владелец — целые).
**Влияет на:** `core/rescaling.md`, `domain/rounding-rules.md`, `components/recipe/ingredients-panel.tsx`.


## ADR-0027 — 2026-10-02 — Публичный сайт из базы: адрес рецепта `/ru/recipe/{slug}`, кэш `io()` → `"use cache"` со сбросом `updateTag`, поисковикам и английскому пока закрыто
**Решение:** публичные страницы — `/ru` (шапка с каталогом + «Новые рецепты», до 12 по дате первой публикации),
`/ru/catalog/{slug}`, `/ru/recipe/{slug}`, `/ru/search` (`app/(public)/[locale]/`). Данные — только опубликованные
(`status = 'published'` в каждом запросе, свои DTO без исходного текста: `lib/server/recipes/public.ts`,
`public-lists.ts`). Схема
рендера: страница → `<Suspense>` (заглушка высотой шапки) → `await io()` → функция `"use cache"` + `cacheTag` +
`cacheLife` (сервер — до сброса или час, браузер посетителя — 30 с; `lib/server/recipes/public-cache.ts`);
`generateStaticParams` — только локали; образ
собирается без БД (CI строит образ до запуска Postgres). После любой успешной записи в кабинете —
`refreshPublicSite()` = `updateTag` всех публичных тегов (`app/(admin)/admin/(protected)/recipes/actions.ts`, `ai-actions.ts`), не
`revalidateTag(…, "max")`: снятый рецепт не должен оставаться видимым. 404 внутри потока «мягкий» (код 200 +
noindex) — принято. Поисковикам закрыто (`SITE_INDEXABLE=false`: robots Disallow, noindex на всех страницах;
`page-metadata.ts` не открывает индексацию, пока сайт закрыт). Английский — позже: `/` всегда на `/ru`
(`i18n/routing.ts`, `localeDetection: false`), hreflang только ru (`LIVE_LOCALES`), `/en` — заглушка noindex,
прочие `/en/*` — 404, кнопки языка в шапке нет. Поиск — в браузере по компактному индексу, состояние в адресе
(`lib/domain/search.ts`, `components/search/recipe-search.tsx`).
**Почему:** владелец 02.10: «Каталог + «Новые рецепты»», «поисковикам ничего не давай пока что, позже сделаем»,
порядок «русский сайт → фото → английский»; пустой раздел в шапке не нажимается (ADR-0020). Критика Codex 02.10:
`io()` вместо `connection()` (не блокирует предзагрузку), без `generateStaticParams` для данных (сборка без БД),
сброс тегов сразу, мягкий 404 без проверки базой в proxy, hreflang только живых языков.
**Альтернативы:** `connection()` (блокирует prefetch); ISR с `revalidateTag(…, "max")` (снятый рецепт виден до
перестройки); `/` по языку браузера (англоязычный посетитель увидел бы пустую заглушку); проверка slug в proxy для
честного 404 (запрос в БД на каждый заход); серверный поиск (рано: индекс маленький).

## ADR-0028 — 2026-10-03 — Фото блюда: одно на рецепт, кадр 4:3 владельца, хранится в Postgres; уменьшение в браузере из-за лимита прокси 1 МБ
**Решение:** у рецепта одно фото готового блюда. В кабинете (`app/(admin)/admin/(protected)/recipes/_components/photo-block.tsx`) владелец выбирает
фото → браузер уменьшает его до ≤ 2000 px и < 850 КБ JPEG (`components/media/shrink-image.ts`) → окно кадрирования
4:3 (`components/media/crop-dialog.tsx`, react-easy-crop: перемещение, щипок, колесо, ползунок, «−/+», стрелки) →
Server Action (`app/(admin)/admin/(protected)/recipes/photo-actions.ts`) присылает фото целиком и рамку долями. Сервер ничему не верит: формат по
содержимому (сигнатура до libvips), ≤ 4,2 Мп, рамка → свой прямоугольник 4:3 не уже 800 px (`lib/domain/photo.ts` `canonicalCrop`), sharp
(`lib/server/media/process.ts`: без кэша, один поток, по очереди, sRGB, без EXIF/GPS/ICC) делает исходник JPEG (хранится
только для «Изменить кадр»), WebP по ширине 480/960/1600 (без увеличения: у узкого кадра — меньше файлов) и превью ссылки 1200×630. Хранение — таблицы
`recipe_photos` (1:1 с рецептом, каскад) и `recipe_photo_files` (`bytea`, `STORAGE EXTERNAL`), миграция 0007. Замена и
смена кадра — новый uuid в транзакции со сверкой прежнего; одна обработка на весь сервер, ≤ 30 в час. Отдача —
`app/media/recipe/[photoId]/[file]/route.ts`: опубликованное всем (`public, max-age=30, must-revalidate`, ETag),
черновик и исходник — только владельцу, остальным 404. Карточка и верх рецепта — одна рамка 4:3 (что выбрано, то и
видно); OG — `og.jpg`. Сброс кэша сайта — как у остальных записей (ADR-0027).
**Почему:** владелец 03.10: «кадрирование, которое я могу двигать и масштабировать на фото, это при загрузке», форма —
«Чуть шире высоты, 4:3». Общий nginx-proxy на проде режет запрос > 1 МБ (замер 03.10: 900 КБ → 405, 1100 КБ → 413),
трогать его нельзя (соседние сайты) — поэтому уменьшение в браузере. Контейнер сайта 0,25 CPU / 384 МБ — обработка
малых входов по одной. Критика Codex 03.10: Postgres вместо тома (транзакционность, каскад, один бэкап и его
проверка), `immutable` противоречит снятию с публикации, ширины по ширине, исходник ради «Изменить кадр», рамку
проверять на сервере, react-easy-crop в модалке без scale-анимации.
**Альтернативы:** том `/opt/recipe/media` как в sup2 (права uid 10001, правки деплоя и бэкапа, «сироты»); повысить
лимит прокси (общий для соседних сайтов); сжатие на лету и next/image (CPU прода); отдельные кадры под каждую
пропорцию; своё окно на pointer events (щипок и iOS).
**Влияет на:** `core/data-models.md`, `domain/recipe-model.md`, `domain/screens.md`, `core/deployment.md`,
`core/access-and-integrations.md`, `deploy/local/recipe-restore-drill.sh`, `.github/workflows/ci.yml`.
