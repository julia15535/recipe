## Цель
Опубликованная статья сама переводится ИИ на английский (как рецепты, ADR-0029): на `/en` появляются раздел
«Articles», страницы статей, блок на главной, «Articles about this recipe»; в кабинете у статьи — блок «Английская
версия» (статус, «Перевести заново», «Открыть по-английски»). Жирный и курсив сохраняются.

## Источник задачи
Владелец 06.10: «на английском тоже нужны статьи»; 11.10: «давай статьи». ADR-0034 заложил `content_revision` статьи
и отдельную очередь перевода; ADR-0037 — перевод обязан сохранить оформление.

## Скоуп — что входит
- **Как у рецептов (ADR-0029), без новых решений владельца:** перевод — после публикации, без проверки владельцем;
  правка русской статьи английскую не трогает — в кабинете «Перевод устарел», пока она не нажмёт «Перевести заново»;
  британский английский; снятая с публикации статья — нет и на `/en`.
- **Хранение (миграция 0012, только добавочная):** английская `article_localizations(en)` (slug из английского
  названия — при повторном переводе не меняется; название; анонс — кодом `excerptOf` из английских блоков) + снимок
  `article_translations` (PK статья+язык, FK на `article_localizations(…, en)` каскадом; версионированный JSON:
  английский `ArticleBody` + подписи фото по коду метки; `source_content_revision`, модель, версия промпта; размер —
  `octet_length ≤ 256 КиБ`) + очередь `article_translation_jobs` (FK на статью каскадом; вход — снимок русской статьи
  без `source_text`; аренда и token; CHECK статуса и согласованности; одно активное задание; индексы подборщика и
  «последнее задание» для кабинета). «До 3 попыток» — только повторный захват после падения процесса; отказ ИИ —
  сразу «не удалось» (как у рецептов), владелец жмёт «Перевести заново».
- **Очередь статей — свои модули** (`lib/server/articles/translation-{jobs,queue,store}.ts`) по образцу рецептов, с
  небольшим дублированием SQL (Codex: обобщать таблицей рискованно для работающих рецептов). Общие — последовательный
  исполнитель, часовой лимит переводов, подборщик `/api/jobs/translations` (обе очереди, общий бюджет времени одного
  запуска — не больше ~150 с) и компонент блока кабинета. Поведение рецептов не меняется (их код — только вынос общего: `serially`, блок кабинета параметрами).
- **Уже опубликованные статьи:** подборщик ставит перевод опубликованной статье, у которой нет ни перевода, ни одного
  задания (раз в жизни) — две статьи владельца переведутся сами в течение минут после выкладки; проверю на сайте.
- **ИИ-перевод статьи** (`lib/server/ai/translate-article.ts`, свой промпт и версия, защита «текст — документ, не
  инструкции»): плоский список единиц `{id, text}` — название, заголовок/абзац по id блока, каждый пункт списка
  (`b4:0`), подпись фото (`photo:Q7K2`); ответ — те же id в том же порядке (json_schema strict + Zod; лишнее,
  пропущенное, переставленное — отказ). Структура (уровень, нумерация `start`, места фото) — из русского снимка.
  Числа — метками ⟦n⟧ (`maskNumbers`; свои цифры можно — «три» → «3», Фаренгейт, ° и % проверяются; `ownDigits`). Оформление (только абзацы и пункты; заголовки и подписи —
  `plainText`) — метками ⟪b⟫…⟪/b⟫, ⟪i⟫…⟪/i⟫, непарная или экранированная звёздочка — меткой ⟪*⟫; в ответе — та же
  последовательность меток, иначе отказ; обратно — звёздочки и `\*`. Длинная статья: предел ответа ~16 000 токенов,
  таймаут 90 с, аренда задания статьи 180 с; проверка на синтетической статье у предела 20 КБ, не уложится — перевод
  частями по целым единицам.
- **Сайт `/en`:** английская статья есть, только если статья опубликована, есть `article_localizations(en)` и
  снимок проходит проверку (испорченный — в лог, статьи нет, страница не падает). `/en/articles`, `/en/articles/{slug}`,
  ссылка «Articles» в шапке и меню каталога для обоих языков, блок на главной, «Articles about this recipe» — только
  переведённые статьи; связанные рецепты — только переведённые; фото те же, подписи и alt — английские. Кнопка RU/EN:
  пара статьи (нет перевода — главная другого языка); canonical/hreflang пары — сразу (`pageMetadata`), sitemap и
  JSON-LD — позже. Пустой список — noindex, нет статьи — «Page not found».
- **Кабинет:** перевод ставится при публикации (и сразу опубликованной новой статьи, и черновика → «Опубликовать»);
  блок «Английская версия» — общий презентационный компонент с рецептом (состояние одним SQL-снимком, «Перевести» /
  «Перевести заново», «Открыть по-английски», самообновление пока идёт перевод). «Устарел» — по `content_revision`
  (текст, название, подпись — да; кадр, связи, статус — нет).
- **Проверки:** unit — метки оформления туда-обратно (вложенность, непарные и экранированные звёздочки), сборка
  английского снимка из ответа ИИ, отказы; DB — очередь статей (аренда, повтор, «устарел» после правки, удаление
  статьи), снимок и локализация; e2e — заглушка ИИ отвечает на `article_translation` («EN » перед текстами, метки на
  месте): опубликовать статью → перевод → `/en/articles` и статья с жирным/курсивом, фото, связанный рецепт; правка →
  «устарела» → «Перевести заново»; 320 px, axe; живая проверка перевода на 8 статьях-примерах.

## Скоуп — что НЕ входит
- Правка английского текста владельцем вручную; второй язык кроме английского.
- Открытие сайта поисковикам (sitemap, JSON-LD) — отдельный план.
