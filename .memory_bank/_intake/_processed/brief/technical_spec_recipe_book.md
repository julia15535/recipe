# Техническое задание: личная авторская книга рецептов

## 1. Концепция

Создать простой, быстрый, mobile-first сайт авторской книги рецептов.

Основной пользователь — владелец сайта. Сайт преимущественно используется как личная книга рецептов, но все опубликованные рецепты доступны по публичным ссылкам для родственников, знакомых и публикации в Instagram.

Основные принципы:

- минимум лишнего функционала;
- максимально быстрая навигация;
- удобство использования с телефона;
- быстрый поиск по рецептам и ингредиентам;
- удобный пересчёт ингредиентов;
- КБЖУ;
- максимально автоматизированное добавление новых рецептов;
- SEO-индексация публичных страниц;
- визуально сайт может ориентироваться на идею домашней, современной и преимущественно здоровой еды.

Референс по структуре каталога:

https://gotovim-doma.ru/

Не копировать интерфейс и сложность Gotovim-doma. Использовать его преимущественно как ориентир для классификации рецептов.

# 3. Умный поиск

Поиск — одна из ключевых функций сайта.

Пользователь должен иметь возможность искать:

- по названию блюда;
- по ингредиенту;
- по нескольким ингредиентам;
- по категории;
- по подкатегории;
- по тегам;
- по сочетанию нескольких условий.

Пример:

Пользователь вводит «курица».

Система сразу показывает варианты:

- Все рецепты с курицей;
- Закуски с курицей;
- Салаты с курицей;
- Супы с курицей;
- Вторые блюда с курицей;
- Выпечка с курицей и т. д.

Другой пример:

`курица + грибы → Вторые блюда`

Поиск должен поддерживать вложенную фильтрацию без необходимости открывать отдельную сложную форму.

Желательно использовать autocomplete:

`тво... → творог`

После выбора ингредиента пользователь сразу видит соответствующие рецепты и может дополнительно ограничить результаты категорией или тегом.

Поиск должен быть удобен для управления пальцем с телефона.

AI для обычного поиска не использовать, если задача решается нормальной индексацией ингредиентов, категорий, тегов и синонимов.

# 8. Ингредиенты

Ингредиенты должны храниться структурированно, а не только текстом.

Для каждого ингредиента:

- canonical ingredient ID;
- отображаемое название;
- количество;
- единица измерения;
- количество в граммах/мл, если возможно;
- КБЖУ на 100 г;
- признак основного ингредиента;
- опциональные комментарии.

Пример:

Творог | 220 | г | основной ингредиент

Яйцо | 1 | шт. | ≈ 55 г

Мука | 50 | г

# 9. Пересчёт рецепта

Одна из ключевых функций.

Не использовать AI при каждом изменении количества.

Все стандартные пересчёты выполняются математически.

## Вариант 1. По количеству порций

Исходный рецепт:

`4 порции`

Пользователь выбирает:

`6 порций`

Коэффициент:

`6 / 4 = 1,5`

Количество всех ингредиентов автоматически умножается на 1,5.

## Вариант 2. По имеющемуся ингредиенту

У рецепта существует основной ингредиент.

Пример:

Сырники:

`творог = 500 г`

Пользователь вводит:

`у меня 220 г творога`

Коэффициент:

`220 / 500 = 0,44`

Все остальные ингредиенты умножаются на 0,44.

При этом пользователь при необходимости должен иметь возможность выбрать не только основной ингредиент, но практически любой количественно измеримый ингредиент и сказать:

`У меня этого ингредиента 350 г`

После чего весь рецепт пересчитывается относительно него.

# 10. Работа с единицами измерения

Для расчётов хранить нормализованные величины.

Предпочтительные базовые единицы:

- граммы;
- миллилитры;
- штуки.

В интерфейсе разрешены привычные обозначения:

- кг;
- г;
- мл;
- л;
- шт.;
- ст. л.;
- ч. л.;
- стакан;
- щепотка и т. д.

Где возможно, один раз определить эквивалент в граммах/миллилитрах и сохранить его.

AI не должен заново определять это при каждом открытии рецепта.

Если при импорте AI определил:

`1 среднее яйцо ≈ 55 г`

результат сохраняется в структуру рецепта.

Для продуктов, где перевод условный, использовать сохранённое приближение.

# 11. КБЖУ

Для каждого ингредиента хранить:

- kcal;
- protein;
- fat;
- carbohydrates;

на 100 г или соответствующую стандартную единицу.

При изменении количества ингредиентов КБЖУ пересчитывается математически.

Показывать минимум:

- КБЖУ всего блюда;
- КБЖУ одной порции.

При изменении порций или количества исходного ингредиента значения обновляются автоматически.

AI для обычного пересчёта КБЖУ не использовать.

Кнопка «Добавить рецепт» доступна только владельцу сайта после авторизации.

Публичные пользователи этой кнопки не видят.

Основная задача — не заставлять владельца вручную заполнять длинную форму.

После нажатия открывается страница импорта рецепта.

Можно предоставить любое сочетание источников:

- написать/вставить обычный текст;
- записать аудиосообщение;
- загрузить фотографию;
- загрузить PDF;
- загрузить Word;
- загрузить текстовый файл;
- добавить основную фотографию готового блюда.

Все поля опциональны.

Можно, например:

1. наговорить рецепт;
2. приложить фотографию блюда;
3. приложить PDF;
4. нажать «Сформировать рецепт».

---

# 13. AI-импорт рецепта

AI применяется прежде всего здесь.

Pipeline:

`Исходные материалы → извлечение текста → AI-структурирование → черновик рецепта → предпросмотр → ручная корректировка → публикация`

AI должен определить:

- название;
- короткое описание;
- категорию;
- подкатегорию;
- дополнительные уровни категории;
- подходящие теги;
- количество порций;
- время приготовления, если указано;
- ингредиенты;
- количества;
- единицы измерения;
- основной ингредиент;
- этапы приготовления;
- данные, необходимые для дальнейшего расчёта КБЖУ.

Если информации нет, AI не должен выдумывать критичные данные.

Неуверенные поля желательно визуально выделять при предпросмотре.

---

# 14. Аудио

На странице добавления рецепта должна быть кнопка записи голосового сообщения непосредственно с телефона.

После записи:

`Audio → Speech-to-Text → AI parser → структура рецепта`

Пример голосового ввода:

«Сырники. Беру 220 граммов творога, одно яйцо, около 40 граммов цельнозерновой муки... Сначала смешиваю...»

Система должна самостоятельно разложить эту речь по необходимым полям.

---

# 15. Фото и документы

AI должен уметь обработать:

- фотографию страницы с рецептом;
- скриншот;
- фотографию рукописной/печатной записи, если текст читается;
- PDF;
- DOC/DOCX;
- TXT.

Из документа извлекается информация и преобразуется в единую внутреннюю структуру рецепта.

---

# 16. Предпросмотр

Ни один AI-импорт не должен автоматически сразу публиковаться.

После «Сформировать рецепт» открыть предпросмотр.

Показать рецепт практически в том виде, в котором он появится на сайте.

Все поля можно отредактировать:

- название;
- категория;
- подкатегория;
- описание;
- ингредиенты;
- количества;
- основной ингредиент;
- теги;
- порции;
- этапы приготовления;
- фото;
- КБЖУ;
- английскую версию.

Кнопки:

- Сохранить черновик
- Опубликовать
- Перегенерировать из исходников

---

# 17. Английская версия

При добавлении/редактировании рецепта автоматически формировать английскую версию через AI.

Русская версия является основной.

Переводить:

- название;
- описание;
- ингредиенты;
- комментарии;
- этапы приготовления;
- категории/теги — использовать заранее заданные английские equivalents там, где они существуют.

После генерации английская версия также доступна в предпросмотре и может быть вручную исправлена.

Для публичного сайта предусмотреть URL-структуру двух языков, например:

`/ru/recipes/...`

`/en/recipes/...`

---

# 18. Авторизация владельца

Административные функции доступны только одному владельцу/ограниченному числу владельцев.

Основной вариант авторизации:

`номер телефона → подтверждение через Telegram`

После подтверждения система создаёт авторизованную сессию.

Неавторизованный пользователь:

- читает рецепты;
- ищет;
- фильтрует;
- пересчитывает ингредиенты;
- переключает язык.

Но не может:

- добавлять;
- редактировать;
- удалять;
- публиковать рецепты.

---

# 19. SEO

Публичные рецепты должны нормально индексироваться поисковиками.

Требования:

- SSR/SSG либо другая SEO-дружественная архитектура;
- уникальный URL каждого рецепта;
- title;
- meta description;
- Open Graph;
- canonical;
- sitemap.xml;
- robots.txt;
- structured data Recipe / Schema.org;
- хлебные крошки;
- человекочитаемые slug;
- отдельные индексируемые страницы категорий;
- подкатегорий;
- тегов;
- русского и английского языка.

---

# 20. Footer

Сделать большой SEO-футер.

В футере разместить ссылки на:

- основные категории;
- ключевые подкатегории;
- популярные теги;
- способы приготовления;
- специальные подборки.

Не превращать основной интерфейс в перегруженное меню — большая структура каталога может находиться преимущественно в каталоге и footer.

---

# 21. Mobile-first

Это принципиальное требование.

Основные сценарии должны быть удобны одной рукой:

- найти рецепт;
- выбрать категорию;
- открыть рецепт;
- изменить количество порций;
- ввести количество имеющегося ингредиента;
- перейти между «Рецепт» и «Приготовление»;
- записать голосовой рецепт;
- загрузить фотографию;
- проверить AI-черновик;
- опубликовать.

Не использовать мелкие элементы и сложные desktop-dropdown.

# 23. Что использовать AI, а что нет

AI использовать:

- распознавание рецепта из свободного текста;
- распознавание голосового сообщения;
- обработка изображения;
- извлечение информации из PDF/Word;
- структурирование рецепта;
- первичное определение категории;
- первичное определение тегов;
- определение основного ингредиента;
- нормализация неоднозначных единиц измерения;
- перевод RU → EN.

AI НЕ использовать:

- обычный поиск, если хватает индекса;
- пересчёт порций;
- пересчёт ингредиентов;
- пересчёт КБЖУ;
- обычную фильтрацию;
- каждое открытие страницы.

После AI-обработки результаты максимально сохранять структурированно в БД и дальше использовать обычную программную логику.

# 24. Приоритет MVP

Для первой рабочей версии обязательно:

1. Главная.
2. Каталог.
3. Категории и подкатегории.
4. Теги.
5. Быстрый поиск по названию и ингредиентам.
6. Карточка рецепта.
7. Одна фотография рецепта.
8. Табы «Рецепт / Приготовление».
9. Пересчёт по порциям.
10. Пересчёт относительно выбранного ингредиента.
11. Автоматический пересчёт КБЖУ.
12. Авторизация владельца.
13. Добавление рецепта.
14. Голос + текст + фото + PDF/Word.
15. AI-структурирование.
16. Предпросмотр и ручное редактирование.
17. Автоперевод на английский.
18. SEO.
19. Полноценная мобильная версия.

Видео, социальная сеть, комментарии, оценки пользователей и сложные пользовательские аккаунты на первом этапе не нужны.

Главная продуктовая идея:

**«Моя личная книга рецептов, где любой рецепт можно найти за несколько секунд, загрузить практически без ручного заполнения и мгновенно адаптировать под то количество продуктов, которое есть дома».**
