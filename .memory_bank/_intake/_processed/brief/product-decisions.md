Продуктовые решения
Целевая аудитория
Сайт должен быть удобен не только владельцу, но и другим пользователям.
Публичные пользователи должны полноценно искать, читать и использовать рецепты.
Главный сценарий
Приоритет №1 — максимально быстро найти конкретный рецепт.
Поиск «что приготовить из того, что есть дома» — не основной сценарий.
Поиск на главной
Сделать простой переключатель:
По рецепту
По ингредиенту
Поиск должен работать максимально быстро, особенно с мобильного.
В режиме «По ингредиенту»:
можно искать один ингредиент;
можно выбирать несколько ингредиентов одновременно;
поиск должен учитывать иерархию ингредиентов.
Пример:
поиск сыр должен находить рецепты с моцареллой, пармезаном, чеддером и другими видами сыра;
поиск моцарелла должен находить только рецепты, где указана моцарелла.
Не делать на главной огромный каталог ингредиентов. Интерфейс должен оставаться простым.
Логика каталога
Основная классификация — по типу блюда:
закуски;
салаты;
супы;
вторые блюда;
выпечка;
десерты;
напитки;
соусы;
заготовки;
разное.
Ингредиенты не являются основной структурой каталога.
Концепция питания
Сайт не является строгим ЗОЖ-проектом.
Основная идея — нормальная домашняя еда с разумным балансом.
Где это не ухудшает вкус, желательно:
уменьшать количество сахара;
не злоупотреблять маслом;
предлагать более полезную замену ингредиента.
Вкус и качество блюда важнее строгого соблюдения диетических принципов.
Публикация
Опубликованный рецепт считается проверенным владельцем.
AI создаёт только черновик.
Без ручного подтверждения рецепт не публикуется.
КБЖУ
На первом этапе КБЖУ считается ориентировочно.
Используются усреднённые значения ингредиентов.
Конкретный бренд и конкретная упаковка не учитываются.
Если тип ингредиента указан явно, он учитывается отдельно: например, моцарелла, пармезан, сливочное масло, оливковое масло.
Точная жирность и конкретный производитель на первом этапе не обязательны.
В будущем базу можно расширить конкретными продуктами и характеристиками.
Ингредиенты
Ингредиенты должны иметь иерархию.
Пример:
Сыр
Моцарелла
Пармезан
Чеддер
Сливочный сыр
Масло
Сливочное масло
Оливковое масло
Подсолнечное масло
В рецепте используется максимально конкретный тип ингредиента, если он имеет значение для результата блюда.
Бренды и товарные позиции на первом этапе не нужны.
Пересчёт рецепта
Пересчёт должен быть кулинарно разумным, а не только математически точным.
Количество, которое ввёл пользователь как исходное, нельзя самовольно менять.
Пример:
Пользователь указал:
мясо = 900 г
Значение 900 г должно остаться неизменным.
Пересчитываются остальные ингредиенты относительно него.
Округление ингредиентов
Для неудобных результатов вроде:
яйцо = 1,4 шт.
нельзя применять одно универсальное математическое правило.
Нужно создать отдельную таблицу правил округления ингредиентов.
Для каждого типа ингредиента определить:
можно ли округлять;
минимальный шаг;
округлять вверх или вниз;
допустимое отклонение от исходной пропорции.
Примеры логики:
яйца → округлять до целых штук по отдельному правилу;
сахар → чаще допустимо округление вниз;
соль → чаще округление вниз;
специи → округлять до практичных мер;
мясо, творог, мука и другие основные количественные ингредиенты → не менять введённое пользователем количество.
Правила округления нужно проработать отдельным этапом перед реализацией пересчёта.
AI не должен каждый раз решать, как округлять. После определения правил они должны храниться в таблице и применяться программно.
Вариации рецепта
Отдельные версии одного рецепта не нужны.
Один рецепт = одна актуальная версия.
При редактировании меняется сам рецепт.
Основные критерии успеха
Приоритеты:
Очень быстро находить нужный рецепт.
Удобно пользоваться рецептом во время готовки.
Очень быстро и просто добавлять новые рецепты.
Удобно делиться рецептами с другими.
SEO-трафик — вторичный приоритет.
